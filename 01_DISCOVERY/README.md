# 01 — DISCOVERY / 소재 탐색

## 목적

좋은 콘텐츠가 될 가능성이 있는 주제를 발견하고 실제 읽은 원문/후기 근거로 후보를 정리하는 역할이다. 현재 작업의 신규 수집은 0이며 문서/Git 정리가 수집 재개 승인이 아니다. 전역 운영/소통/권한은 [AGENTS](../AGENTS.md), 저장/CAP·형식은 [data 계약](../data/README.md)을 따른다.

입력은 두 종류다.

- 자동/반자동 탐색: Google Trends, YouTube 메타데이터, NAVER 검색/트렌드, 허용된 RSS/API, 공개 검색 인덱스
- 사용자 직접 제보: URL, 캡처 요약, 직접 작성한 내용, "이거 소재로 봐줘" 같은 메모

## 탐색은 테마별 레인으로 분리

한 번에 전부 섞어 찾지 않고, 최소 다음 레인을 따로 본다.

- 웃긴 짤 / 밈
- 커뮤니티 논란 / 의견갈림
- 소식 / 이슈 / 지금 뜨는 것
- 직장 / 취업 / 회사썰
- 연애 / 인간관계
- 돈 / 소비 / 재테크
- 군대 / 학교
- 황당 / 실화 / 반전
- AI / IT / 게임
- 연예 / 방송 / 문화
- 스포츠 / e스포츠
- 음식 / 여행 / 장소
- 동물 / 자연

테마 자체의 분류 기준은 `app/features/themes/`가 소유하고, 어떤 플랫폼에서 그 테마를 우선 찾을지는 `app/features/discovery/sources/`가 소유한다.

## 플랫폼도 분산

특정 커뮤니티 하나에 의존하지 않는다.

현재 Registry 범위:

- Google Trends
- NAVER 뉴스 / 블로그 / 카페
- Daum 카페
- YouTube
- Reddit
- X / Twitter
- Threads
- Instagram
- DCInside
- Blind
- FMKorea
- 더쿠
- 인스티즈
- 클리앙
- 루리웹
- 인벤
- 뽐뿌
- 아카라이브
- Tistory / 공개 블로그
- 기타 뉴스 / 공개 웹

중요: Registry에 등록됐다고 자동 크롤러가 있다는 뜻은 아니다. 실제 adapter 상태를 `connected / connected-when-credentialed / manual-only / planned`로 따로 기록한다.

DCInside/Blind처럼 자동 대량 수집을 쓰지 않는 출처는 허용된 공개 검색 메타데이터·개별 공개 원문 수동 읽기·사용자 URL/캡처를 근거로 한다. 자동 대량 crawler나 인증/학교/성별/회원등급·CAPTCHA 우회는 하지 않는다. [SOURCE_POLICY](../docs/SOURCE_POLICY.md)의 당시 약관 기록과 재확인 경계를 따른다.

## 이 파트가 하는 일

- 주제 후보 발견
- 탐색 레인/테마 기록
- 원 출처/발견 플랫폼 기록
- 왜 눈에 띄었는지 1~3줄 메모
- 공개 반응값이 있으면 조회/좋아요/댓글/순위 기록
- 중복 후보/유사 토픽 표시
- Audience Comfort 초벌 차단
- RED/YELLOW/GREEN 소스 위험도 초벌 분류
- 발견 시각 기록

## 하지 않는 일

- 사실관계를 최종 확정하지 않는다.
- 80점, 95점 같은 최종 콘텐츠 점수를 확정하지 않는다.
- 후보 표시제목·draft caption/태그를 기록할 수 있지만 최종 제작 대본/게시문안 확정·게시 승인을 만들지 않는다. [HANDOFF](../docs/HANDOFF_CONTRACTS.md)의 final_draft 금지와 구분한다.
- 실제 게시하지 않는다.
- 커뮤니티 원문 전체를 자산처럼 저장하지 않는다.
- 출처 이용조건을 확인하지 않은 사이트에 대량 본문 크롤러를 임의로 붙이지 않는다.

## 출력 — Candidate Packet

최소 필드:

```text
candidate_id
found_at
found_by            auto / user / manual
discovery_lane      funny_memes / community_debate / ...
discovery_source    reddit / x / blind / dcinside / naver_cafe / ...
source_type
source_url
source_risk         green / yellow / red
topic_title
why_interesting
raw_signals         검색량/조회/발행시각 등 실제로 있는 값만
related_sources[]
notes
```

값을 모르면 `unknown/null`로 둔다. 추측해서 채우지 않는다.

## 사용자 직접 제보 처리

사용자가 글 내용을 직접 올린 경우에도 그 내용을 곧바로 사실로 확정하지 않는다.

```text
사용자 제보
→ Candidate Packet
→ 02 EDITORIAL & SCORING에서 독립 검증
```

## 완료 기준

`02_EDITORIAL_SCORING`이 바로 조사할 수 있을 정도로 **무엇이 화제인지 + 어떤 테마인지 + 어디서 발견했는지 + 왜 볼 가치가 있는지**가 정리되어 있으면 끝이다.

## 원문 충분함·다양성·길이 선별

- 개별 공개 원문을 처음부터 실제 끝/결말까지 읽고 필요한 연결 후기와 동일 사연 재게시를 대조한다. 같은 글/후기는 한 사건으로 묶고 원래 관측과 재열람 시점/cache/수치는 분리한다. 제목·검색 snippet·URL-only를 완독/실파일 확보로 세지 않는다.
- 공개 에타/여시 재보도는 실제 읽은 재보도 URL·원제·기사 귀속을 기록한다. 원플랫폼 원본·핵심 캡처 픽셀·진위 미검증이면 그대로 표시하고 원글을 읽은 척하지 않는다. 독립 기사에 전개/끝이 충분하면 그 텍스트 근거만 쓰며 캡처가 핵심이면 전체 픽셀 판독 전 보류한다.
- 테마/플랫폼을 분산하고 사건·전개·후기 충분함을 우선한다. 300개 등 숫자 quota를 강제로 채우지 않으며 짧은 몇 줄을 늘려 사건 문단을 억지로 만들지 않는다.
- 실제 원문 전체와 이미지 역할/후기까지 보고 **실용 예상 24장 이하**로 선별한다. **25장 이상 예상 초장문 후보는 제외**한다. 이것은 렌더 실측 완료 주장이 아니며 요약/캡션 길이·사진 개수만으로 판단하지 않는다. 결말/본문을 잘라 24장으로 통과시키지 않고 경계가 불명확하면 보류한다.
- 원문의 개별 불펌 금지, 민감/신상 위험과 공통 copyright footer를 구분한다. 안전하지 않은 원문 문맥을 caption에서 지워 숫자만 채우지 않는다. 권리/접근 기준은 SOURCE_POLICY, C/A/P는 data 계약을 유지한다.

## 설명글 초안과 태그 — 이 파트의 권위

plain 첫 제목 뒤에 **순수 기사체 3~5개 사건 문단**으로 실제 경과/결말을 작성한다. 수집자 메타·이미지 관측·수치·권리 경고는 문안 밖 근거에 둔다. 글쓴이 자기보고/기사 주장/수집자 작성 의견을 구분하고 실제 댓글·감정·동기·후기·새 사실을 발명하지 않는다. 미결말이면 실제 끝 상태를 그대로 기록한다. 원문/표시제목 경계는 [TITLE_STYLE_GUIDE](TITLE_STYLE_GUIDE.md).

태그는 caption의 **마지막 별도 단락**이며 사건 문단 수에서 제외한다. 전체 caption 문자수에는 제목·문안·태그를 포함한다. 길이/출처 이용 한계가 넘으면 표시하고 사건/결말을 잘라 숨기지 않는다. 기존 운영 문안/태그를 이번 형식·문서 정리로 일괄 재작성하지 않는다.

- 사연: `#썰 #사연` + 본문에 직접 관련된 주제 2~3개, 총 **4~5개**.
- 정보: 억지 공통 사연 태그 없이 주제 중심 **3~5개**.
- 전체 본문/결말을 읽고 선택하며 제목 자동 토큰·사이트명·무관 유행·어색하게 문법상 조사 붙인 태그·진지 사연의 유머·일반 이미지 자료의 릴스 태그·중복을 금지한다. 여기서 '조사'는 문법상 조사이며 실제 경찰 조사 경험 단어 자체를 금지하는 새 정책이 아니다.
- 태그 결정은 주제 분류이지 권리 허가나 제작/게시 승인 확정이 아니다. draft caption/tags의 소유권은 01, 최종 제작은 03, 실제 게시 권한은 04다.

## 기존 원문을 선별 ZIP으로 넘기는 기준

후보를 읽을 때 원문 제목, 사용할 본문 문장과 순서, 실제 본문 이미지 파일과 들어갈 위치, 사용할 댓글의 원문·위치·반응 근거, 첫 장의 짧은 문구와 실제 배경이 될 원문 조각을 함께 적습니다. 페이지 전체 HTML이나 댓글 목록을 본문으로 묶지 않습니다. 무엇을 넣을지 확정하지 못하면 `확인 필요`로 남기고 이미지 제작으로 넘기지 않습니다. [원문 ZIP 작성 가이드](../docs/SOURCE_BUNDLE_GUIDE.md)를 따릅니다. 기존 후보를 추측해서 일괄 완료로 승격하지 않습니다.

## 중간 문구도 소재를 찾을 때 함께 작성

새 소재를 실제로 읽고 기록할 때 `## 중간 문구 초안`을 함께 작성합니다. 표지 제목 외에 본문 사이/끝에 넣을 짧은 의견 또는 질문 1~3개, 넣을 위치, 원문 근거를 적습니다. 본문을 읽지 못한 후보는 내용을 만들어 채우지 않고 `본문 확인 후 작성`으로 남깁니다.

- 형식: `위치: 원문 어느 대목 뒤 / 작성 의견: 짧은 문구 / 근거: 실제로 확인한 대목`.
- 작성한 의견을 실제 이용자 댓글이나 여론으로 표시하지 않습니다. 원문 댓글을 직접 인용하면 실제 확인한 짧은 인용과 출처를 별도로 남깁니다.
- 숫자·의도·질병·법률 등 새 사실을 추측해 추가하지 않습니다. 의견 문구는 제작 초안이며 사실 검증·게시 승인 상태를 올리지 않습니다.
- 기존 소재를 읽지 않고 일괄 자동 생성하지 않습니다. 새로 찾거나 다시 확인한 소재부터 적용합니다.
- 앱 후보 동기화 → 컷 편집기의 `소재를 찾을 때 적어둔 중간 문구`로 전달합니다. 사용자가 원하는 장의 위/아래에 옮겨 배치합니다.
