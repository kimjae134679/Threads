# 후보 한 건 = 파일 하나

이 폴더가 사람이 보는 기본 Discovery 목록이다. 파일명만 봐도 날짜/후보단계/자산생성/게시상태를 알 수 있다.

- `C0`: 제목은 찾았지만 정확한 개별 원문 URL 또는 provenance가 아직 부족함
- `C1`: 정확한 원문/공개 URL을 확인함
- `C2`: 제작 후보로 선택됨. rights/privacy/human approval은 별도
- `A0`: 실제 source-backed 이미지/캐러셀 미생성
- `A1`: 실제 source asset 기반 사용자용 결과물 생성 확인
- `P0`: 미게시
- `P1`: 04가 실제 게시 성공 확인

후보 파일 안에는 **제목 / 확인된 글 내용 요약 / 정확한 링크 / 동일 시점 관측 수치 / 평가 / 형식 / 자산·게시상태**만 중심으로 적는다. 개발용 schema나 프로그램 코드 설명은 넣지 않는다.

## 형식
후보 형식은 아래 세 개만 사용한다.

- `글` — 텍스트 중심. 콘텐츠 이해에 필요한 원문 이미지 없음.
- `이미지` — 글 + 첨부 이미지/사진/뉴스 캡처가 함께 있음. 글과 이미지를 같이 확보한다.
- `이미지 포스팅` — 이미지/카드/슬라이드/스크린샷 자체가 본문 중심. 원래 순서대로 전체 이미지를 확보한다.

세부 미디어 타입은 만들지 않는다. 새 후보 파일에서 `CAROUSEL_SOURCE`, `NEWS_CARD_POST`, `SCREENSHOT_POST` 같은 분류를 사용하지 않는다.

## 중간 문구도 소재를 찾을 때 함께 작성

새 소재를 실제로 읽고 기록할 때 `## 중간 문구 초안`을 함께 작성합니다. 표지 제목 외에 본문 사이/끝에 넣을 짧은 의견 또는 질문 1~3개, 넣을 위치, 원문 근거를 적습니다. 본문을 읽지 못한 후보는 내용을 만들어 채우지 않고 `본문 확인 후 작성`으로 남깁니다.

- 형식: `위치: 원문 어느 대목 뒤 / 작성 의견: 짧은 문구 / 근거: 실제로 확인한 대목`.
- 작성한 의견을 실제 이용자 댓글이나 여론으로 표시하지 않습니다. 원문 댓글을 직접 인용하면 실제 확인한 짧은 인용과 출처를 별도로 남깁니다.
- 숫자·의도·질병·법률 등 새 사실을 추측해 추가하지 않습니다. 의견 문구는 제작 초안이며 사실 검증·게시 승인 상태를 올리지 않습니다.
- 기존 소재를 읽지 않고 일괄 자동 생성하지 않습니다. 새로 찾거나 다시 확인한 소재부터 적용합니다.
- 앱 후보 동기화 → 컷 편집기의 `소재를 찾을 때 적어둔 중간 문구`로 전달합니다. 사용자가 원하는 장의 위/아래에 옮겨 배치합니다.
