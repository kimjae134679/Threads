# 원문 선별 → ZIP → 게시용 이미지

현재 화면: `npm start` 후 `http://127.0.0.1:4173/app/source-batch.html`.

기존 후보 목록에서 관심 있는 글은 **이 글만 수집**으로 한 건씩 원문을 모읍니다. 전체를 처리하려면 **기존 원문 모으기**를 사용합니다. 저장된 HTML과 연결 이미지 후보를 로컬에 보관합니다. 이것만으로 게시용 이미지가 완성되지는 않습니다. 각 행에서 **원문 선별**을 열고 원문 제목, 필요한 본문 글 조각, 원본 이미지와 위치, 실제 댓글, 첫 장 문구와 배경으로 쓸 원문 조각을 확인합니다. 자동 초안은 확인한 게시글 본문 영역만 대상으로 문단을 묶고, 실제 댓글의 반응 근거가 있는 최대 세 건을 제안합니다. 원문과 대조했음을 자동으로 표시하지 않으며, UI 문구나 누락된 이미지가 있는지 사람이 확인해야 합니다.

**확인 후 ZIP 저장·이미지 제작**으로 현재 선택에서 원문 ZIP과 PNG ZIP을 연달아 저장할 수 있습니다. **현재 선택으로 미리보기**는 검수 전 표시가 있는 예시를 만듭니다. **원본·선별 기준 ZIP만 저장**으로 원본 바이트·선별 기준·이미지 파일·해시만 따로 묶을 수도 있습니다. 작성 중인 ZIP은 `needs_selection`이며 게시용 이미지가 아닙니다. 본문·이미지·댓글 확인과 첫 장의 원문 글/이미지 배경이 모두 완료된 ZIP만 PNG 세트로 제작합니다. 단색 제목 표지는 만들지 않습니다.

## 기존 후보 입력 폴더

저장소 루트에서 아래 명령을 실행하면 기존 후보를 읽기 쉬운 프로그램 입력 묶음으로 정리합니다.

```sh
node scripts/normalize-existing-candidates.mjs --write
node scripts/normalize-existing-candidates.mjs --check
```

결과는 `data/runtime/program_inputs/`에만 저장되며 Git에 올라가지 않습니다. 중복은 정확히 같은 게시물 URL인 경우에만 한 묶음으로 합칩니다. `candidate.md`에는 묶인 원래 후보 기록과 파일 경로·해시, `manifest.json`에는 URL·상태·Jev 평가 경로와 실제 값, 과거 묶음·미디어 출처를 기록합니다. 확인되지 않은 원문은 빈칸/미확인으로 두며 요약을 원문으로 바꾸지 않습니다. 실제 연결이 확인된 TheQoo 원본 이미지가 있을 때만 `media/`에 복사하고 SHA-256을 다시 확인합니다.

이 입력 묶음의 `content.txt`는 후보/기존 요약 기록이지 원문 전문 TXT가 아닙니다. 화면의 **원본 폴더 선택**에 바로 넣지 마세요. 앱에서 **기존 후보 목록 → 이 글만 수집**으로 원문을 확보한 다음 선별 화면에서 사용합니다. 자동 수집은 저장소 규칙에 따라 기존 정확한 공개 URL만 사용하고 Blind/DCInside는 자동 수집하지 않습니다.

## 직접 가진 원문 폴더

저장한 원문 HTML 또는 원문 그대로의 TXT/JSON과 첨부 이미지를 선택할 수도 있습니다. TXT 형식은 다음과 같습니다.

```text
[TITLE]
원문 제목
[BODY]
원문 글 그대로. 줄바꿈과 공백을 변경하지 않습니다.
[IMAGE:photo1.jpg]
이미지가 놓인 원문 위치 바로 다음 문장
[COMMENTS]
[+123] 인기 댓글 원문
[+45] 두 번째 댓글 원문
```

TXT는 파일 자체가 원문일 때만 사용하세요. `content.txt`의 BODY_SEQUENCE 요약은 원문으로 판정하지 않습니다. JSON은 `schema=threads-verbatim-source-v1`, `verbatim=true`, 원본 제목·본문·실제 댓글이 있어야 합니다.

수집 파일과 실제 입력 ZIP은 로컬 `data/runtime/source_pipeline/` 또는 선택한 PC 폴더에 있습니다. 권리·개인정보·최종 결과물 검수는 04 단계에서 별도로 진행합니다.
