# 게시글 제작 기반 — 2026-10-06
최신 사용자 지시는 이미지 수를 적당히 제한하고 제목·글씨·내용·장 구성·운영 기반부터 완성하는 것이다. 수집 레퍼런스 수준 이상을 목표로 하되 자동 파일 검사를 시각 품질 승인으로 표현하지 않는다.

## 글 한 건의 제작 기준

| 요소 | 현재 규칙 | 검수할 판단 |
|---|---|---|
| 제목 | 원제 보존 + 별도 표지 문구·줄바꿈·최대 3개 핵심 강조 | 관계·사건이 첫눈에 읽히며 반대 의견·결말을 왜곡하지 않는가 |
| 제목 근거 | 원문 문구와 source ID 기록, 문자열 일치 상태 표시 | 문구가 존재하는 것과 제목 의미·사실 검증은 별개 |
| 표지 | 이미지가 의미를 돕는 일부만 사진형; 나머지는 민트·진녹색 제목 디자인 | 평범한 반복 사진을 억지로 붙이지 않고 소재별 상황을 표현 |

| 보완 이미지 | 원문과 분리된 표지 전용 이미지, SHA·출처/라이선스·AI 설명·관련성 기록 | 실제 사건·당사자 사진으로 오인시키지 않는가 |
| 검수 화면 | 한 열 순서대로 읽기, 여러 장 비교, 표지·본문·댓글·마지막 장 바로 이동 | 갤러리 열기·생성 성공은 검수 완료가 아님 |

사진 안에 글·도표가 있으면 전체 화면을 보존하고 제목을 아래 별도 영역에 둔다. 피사체를 살리는 사진과 대비 높은 제목을 결합한다. 차분한 정물의 반복 대신 상황·표정·갈등이 보이는 이미지를 적당히 사용한다. 사용자가 확정한 제목·두 핵심 문구 강조는 유지한다.

원문 누락·접근 제한·불명확 주소·누락 미디어·안전 분할 불가 상태는 보완 표지로 통과시키지 않는다. 원문은 별도 비공개 입력에 있고 공개 저장소에는 코드·기준만 보존한다. 원문 댓글을 만들거나 요약을 원문으로 처리하지 않는다.

## 이번 대표 편집
실제 저장한 20건 원문을 다시 읽어 제목·줄바꿈·강조·근거를 편집했다. 결혼 비용은 축의금과 여행 경비의 합인지 구분하고, 2018년 비용은 연도를 표시한다. 신랑신부 포함 10명 **이하**를 미만으로 바꾸지 않는다. 사연의 퇴사 요구는 당사자 주장이라는 표현을 유지한다. 노동청과 법원 판단이 갈린 특정 사건을 일반 법률 결론으로 확대하지 않는다. 비혼 축의금 논쟁은 양쪽 입장이 본문에 남는다. '버거운'을 햄버거 소재로 분류한 오배정은 제거했다.

6개 표지에 이미 만든 5종 AI 상황 이미지를 적용하며, 나머지 제목형·관련 사진과 함께 비교한다. 생성 요청 설명은 세션에서 복원한 요약이라는 사실을 출처 JSON에 적는다. 실제 생성 요청 전문과 동일하다고 주장하지 않는다. 제작 결과 전체와 대표 표지·본문 첫/중간/마지막 장을 따로 검수한다.

## 현재 작업 흐름과 향후 자동화

현재는 저장 자료에서 제작하며 생성·검수·게시를 분리한다. 원문과 제작 규칙·편집·보완 이미지의 해시로 변경을 식별한다. 20건마다 진행 기록과 목록을 저장하고, 같은 입력과 결과 해시이면 재제작을 건너뛴다. 게시 기록이 있는 항목은 재제작 대상에서 제외한다. 변경된 결과는 검수 전으로 돌아간다.

다음 구현 순서는 다음과 같다.

1. 대표 결과의 제목·가독성·장 흐름을 실제 검수하고 반복 실패를 수정한다.
2. 검수 피드백을 글·페이지·원문 근거와 연결해 기록하고 변경 시 승인 무효화를 유지한다.
3. 공식·허용된 자료 수집에 중복 제거·출처 시각·재시도·제한·실패 큐를 적용한다.
4. 수집→검증→편집→제작→사람 승인→공식 게시의 단계별 입력·상태·재개 조건을 연결한다.
5. 품질 기준을 충족한 뒤 스케줄과 운영 감시·성과 학습을 연결한다.

현재 자율 수집 스케줄·무승인 게시를 켠 상태가 아니다. 실제 게시 성공은 플랫폼 ID/응답/URL로만 기록한다. 권리·개인정보·사실 검증 및 사람 승인 체인은 기존 AGENTS/HANDOFF_CONTRACTS를 따른다.
