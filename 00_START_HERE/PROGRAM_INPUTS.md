# 프로그램 자료 사용 안내

## 통합 루트의 현재 입력 계약

현재 통합 입력은 후보마다 `자료.txt` 한 파일입니다. 사람 영역의 원문링크/표시제목/본문(전문 또는 명시 요약)/Instagram·Threads 전체 문안과 해시태그를 함께 읽습니다. 별도 구분선 뒤 프로그램 영역은 기존 ID·원제·정확 URL·버전·sourceFingerprint/ruleVersion/reviewRound·댓글·이미지 순서/해시·권리·판정·provider 상태를 손실 없이 보존합니다. 제목 정리는 표시 영역만 적용하며 raw 원제를 변경하지 않습니다. 요약은 실제 전문/이미지 판독이나 생성 승인으로 간주하지 않습니다.

`local-private/project/자료`, `local-private/production-inputs`, `local-private/operating-studio`는 원본을 보존한 비공개 사본입니다. 예전 1,084 원본 입력, 현재 199 게시 검토, 365 과거 리뷰 회차, 780 미제작 수집 후보는 서로 다른 범위입니다. 파일 총수/같은 ID/읽은 장/이전 통과를 현재 게시 승인으로 합치지 않습니다. 소급 MD/TXT 변환은 원파일 SHA·파일명 원키/별칭을 보존하고 제외 감사 자료를 활성화하지 않습니다.

프로젝트 루트 `upload-studio/START.ps1` 또는 `node upload-studio/server.mjs --project-root .`로 같은 서버를 엽니다. `/materials/`에서 전체 자료, `/`에서 같은 글·버전의 문안/검토, `/viewer/`에서 현재 이미지 전체를 봅니다. 문안과 태그는 각각 복사할 수 있지만 파일 저장은 **한 TXT**입니다. 원본 바이너리와 법적 라이선스/생성 프롬프트는 성격을 구분해 보존하며 게시문안으로 합치지 않습니다.

아래 분리 폴더 설명과 2026-10-04 숫자는 **기존 입력/당시 기록**입니다. 호환 reader와 비공개 이력의 설명이지 신규 분리 출력이나 현재 판정 집계가 아닙니다.

바탕화면 **Threads Cut Editor 자료 → 01_후보 기록**이 기본 입력입니다. 0.3.1의 **전체 자동 제작**을 누르면 저장된 원문을 우선 읽고 자료와 연결 이미지가 충분한 항목을 한꺼번에 제작합니다. 다른 자료만 **다른 폴더**를 선택합니다.

## 후보 한 건의 구조

- `자료 안내.txt`: 현재 상태, 보류 사유, 다음 조치.
- `제작 계획.md`: 제목·본문·이미지·댓글 순서와 장별 배치.
- `source/`: 저장 원문 HTML/TXT/JSON, 실제 원본 이미지, 수집 기록.
- `media/`: 기존 원본 이미지가 있는 후보만.
- `작업 정보/`: 자동 처리 상태, 기준 버전, 수집·제작 계획, 검수·게시 기록.
- `참고 기록/`: 이전 candidate.md/content.txt/comments.txt 요약. 실제 원문을 대신하지 않습니다.
- `manifest.json`: 기존 후보 ID와 출처 연결.

자료 형식과 커뮤니티별 접근 방법은 [원문 입력 안내](../docs/COMMUNITY_SOURCE_INPUT.md)를 봅니다. 프로그램이 폴더 구조를 다시 읽고 상태를 기록하므로 사람이 완료 마킹을 직접 할 필요는 없습니다.

## 결과와 기준

결과는 **06_자동 제작 결과 → 자료 목록.html / 현재 결과**입니다. 앱에서 제목·보류 사유·제작일·기준 버전·검수·게시 상태를 확인합니다. 동일 자료·기준·결과 해시는 건너뛰고 변경/누락 결과는 다시 제작합니다.
