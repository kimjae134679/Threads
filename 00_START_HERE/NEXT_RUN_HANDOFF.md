# Threads 콘텐츠 자동 제작 — 전체 작업 인수인계

문서 기준: 2026-10-04 한국 시간. 작성자: 07-Codex-Handoff.
이 문서의 목적은 공유 대화 링크를 읽지 못하는 다른 AI나 담당자가 현재 상태부터 작업을 재개할 수 있게 하는 것이다. 대화 전체의 녹취가 아니라 요구사항·결정·실제 변경·검증·파일 위치·남은 작업을 정리한 현재 상태 기록이다.

## 1. 가장 먼저 알아야 할 결론

저장 자료를 폴더 단위로 처리하는 Windows 프로그램은 0.3.1까지 구현·배포했다. 실제 후보 1,084건에서 검수 전 결과 417건, PNG 2,886장을 생성했다. 재실행 때는 기존 결과 417건을 건너뛰었다. 나머지 667건은 원문·접근·정확한 URL·이미지 등의 조건이 부족하다.

Instagram 레퍼런스는 공개 계정 7개에서 각 6게시물, 총 42게시물과 원본 이미지 200파일을 저장·분석했다. 전체 장 확보 40게시물, 부분 수집 2게시물이다. 기획서는 10페이지이며 원본·캡션·장 순서·날짜·해시·계정별 분석·오프라인 이미지 목록을 ZIP으로 전달했다.

그러나 사용자가 기대하는 레퍼런스 수준의 편집 품질과 모든 자료의 완전 자동 제작을 완료했다고 선언할 수 없다. 자료별 템플릿 선택, 의미에 따른 장 구성, Instagram 일정 비율 조판, 360px 가독성 평가 등은 기획된 추가 구현이다. 파일 무결성 검사 통과는 전체 내용 검수나 사용자의 만족 확인이 아니다. 실제 게시 확인은 0건이다.

## 2. 사용자가 요구한 것과 판단 기준

- 사람이 자료를 하나하나 편집하지 않아도 폴더를 선택하거나 기본 폴더의 전체 자동 제작을 누르면 처리되어야 한다.
- 기본 입력은 이미 저장한 원문·이미지다. 링크는 출처와 누락 자료 보완용이며 링크 문자열만 있는 카드를 결과로 만들지 않는다.
- 자료 수집 단계에서 표지 제목, 본문, 이미지, 댓글, 작성 의견, 장 순서와 배치 근거를 미리 결정하고 저장한다.
- 원문 내용을 실제로 읽고 정확한 제목·개별 URL·필요한 이미지·끝맺음을 확보한다. 검색 요약, 메뉴, 사이트 UI를 원문 본문으로 섞지 않는다.
- 가로 사진을 긴 세로 캔버스로 늘리거나 의미 없는 큰 여백을 붙이지 않는다. 제목 위치·안전 여백·큰 글자·원문 읽기 순서가 중요하다.
- 표지와 본문, 댓글에서 의도 없는 중복을 없앤다. 제목 아래 원문이 가려지거나 문장·말풍선이 중간에서 끊기면 실패다.
- 생성 여부, 최신 기준 버전, 원문 확인 시각, 생성 시각, 검수 여부, 실제 게시 여부를 사람이 쉽게 확인할 수 있어야 한다.
- 원본은 보존한다. 이전 파생 결과·구버전 설치파일·임시 예시를 최신 결과 검증 후 정리한다.
- 부족한 자료는 AI가 가능한 범위에서 찾아 보완하고 정확한 부족 사유와 다음 조치를 남긴다. 없는 내용은 만들지 않는다.
- Blind·DC·여성시대 등 접근 조건이 있는 사이트의 실제 입력 방법을 문서화한다. 접근 실패를 읽기 성공이나 본문 확보로 처리하지 않는다.
- 긴 작업은 독립 작업을 병렬로 진행하되 같은 파일을 동시에 수정하지 않는다. 현재 사용자는 병렬 작업과 GitHub 정리를 명시적으로 요청했다.
- 프로그램을 직접 켜고 실제 예시 결과를 확인하는 것이 필요하다. 계획이나 테스트 통과만으로 최종 품질을 주장하지 않는다.
- 인수인계는 한 진입 문서와 주제별 단일 THREAD.md에 연결한다. 이전 대화 기억에만 의존하지 않는다.

## 5. 사람이 보는 폴더와 자료 한 건의 구성

전체 자료 폴더에는 00_먼저보기, 01_스타일 레퍼런스, 01_후보 기록, 03_배포 설치파일, 06_자동 제작 결과를 남겼다.

후보 한 건의 폴더는 제목과 ID로 식별한다. source/는 원문·이미지, 자료 안내.txt는 상태와 다음 행동, 제작 계획.md는 사람용 장 구성, 작업 정보/는 기계 상태, 참고 기록/은 과거 요약이다. 과거 요약을 실제 원문으로 사용하지 않는다.

입력 색인은 실제 입력 루트의 index.json(schema threads-program-input-index-v1)이다. 후보별 manifest.json과 필요한 media/도 있다. 작업 정보/의 실제 파일은 automation-status.json, capture-plan.json, production-plan.json, workflow-state.json이다. 결과 원장 status.json의 schema는 threads-auto-batch-v1이고 제작 계획 schema는 threads-production-plan-v1이다. 계획에는 원제·표지 제목·제목 근거·sourceSha256·bundleSha256·제외 근거·경고·장별 operation/sourceId/실제 크기를 보관한다.

결과 한 건의 현재 폴더에는 source-bundle.zip, review-preview.zip, rendered/의 PNG, production-plan.json 등이 있다. source-bundle.zip은 원문 증거, review-preview.zip은 검수 전 결과다. 생성 상태와 검수·게시 상태는 별도로 읽는다.

새 Discovery 기록은 data/candidates/의 한 후보당 Markdown 한 파일이다. 과거 raw batches와 개발 demo를 사용자용 최종 결과로 보지 않는다. 파일명의 C/A/P는 출처 확인·자산 생성·실제 게시를 구분한다. A1이 P1을 뜻하지 않는다.

## 6. 현재 프로그램에서 실제로 되는 것

1. 기본 저장 자료 폴더의 전체 자동 제작, 다른 폴더 선택, 진행·중지·재시작·결과 탐색.
2. 저장 HTML, 원문임이 명시된 TXT/JSON, 연결된 실제 이미지, 기존 Source Package 입력. TXT는 [TITLE]과 [BODY]가 필수이며 [IMAGE:파일명] 및 [COMMENTS]를 사용한다. JSON은 schema threads-verbatim-source-v1, verbatim=true, 실제 title/body를 요구한다.
3. 기존 주소의 공개 원문 보완: 더쿠·인벤·네이트판. 새 소재 무제한 발견 기능이 아니다.
4. 원문 부족·접근 제한·주소 불명확·이미지 부족·선별 필요 등을 구체적인 사유와 다음 행동으로 표시.
5. PNG 렌더링 전에 원문 기반 제목·본문·이미지·댓글의 제작 계획을 저장.
6. 제작 기준 2026-10-04.1: 폭 1080px, 내용에 맞춘 높이 608~1350px, 안전 여백 64px, 제목 64~84px·최대 42자/3줄, 본문 46px.
7. 사진 비율 유지, 긴 이미지 전체 영역의 분할, 원문 순서 보존, 표지·본문의 불필요한 완전 중복 처리.
8. 본문과 댓글의 표시용 URL·구분선·완전 중복을 제외하고 원문과 제외 근거는 보존.
9. 원문·규칙 버전·원문 ZIP·PNG 해시가 일치하면 기존 결과 건너뜀. 출력 누락 또는 원문/기준 변경은 재처리.
10. 동시 실행 잠금과 중단 후 상태 보존. Windows 일시적 파일 잠금에 고유 임시파일과 제한된 재시도로 대응.
11. 결과 목록에서 제목, 제작일, 기준 버전, 검수 상태, 게시 상태와 다음 조치를 확인.
12. 확인된 게시 URL·시각이 있는 게시 완료 항목을 재제작에서 제외. 근거가 없는 게시 여부는 unknown.

입력 제한은 저장 HTML 1개·5MB, 이미지 최대 30개·파일당 25MB·합계 60MB다. 중복 후보 ID는 오류이고 결과 폴더는 입력 폴더 밖에 있어야 한다. 실제 입력 우선순위는 후보 루트/source의 source.json·source.txt·HTML 후 저장 이미지/기존 Source Package다. content.txt 같은 후보 요약과 Jev 평가는 원문 전문으로 사용하지 않는다.

이 목록은 의미별 자동 편집을 전부 해결했다는 뜻이 아니다. 현재 긴 이미지는 전체 보존을 위한 분할이며 대화·문단 의미를 완전히 이해한 장 구성은 추가 개선 대상이다.

## 12. 개발 진입점과 실행 명령

root package는 threads-ai-content-lab 0.42.3이고 desktop package는 threads-cut-editor 0.3.1이다. 서로 다른 버전이며 웹 앱 버전을 Windows 실행본 버전으로 쓰지 않는다. Node.js 24 이상이 필요하다.

코드 폴더에서:
```powershell
Set-Location 'C:\KJ\Github\Threads'
npm start
# 웹 앱: http://127.0.0.1:4173/app/
npm run start --prefix desktop
npm run check
npm run smoke:auto --prefix desktop
npm run smoke:curation --prefix desktop
npm run pack:win --prefix desktop
```

사용자는 개발 명령 대신 바탕화면 바로가기와 전체 자동 제작을 사용한다. 개발 smoke는 분리된 임시 자료로 수행하고 실제 원본을 테스트 입력으로 변경하지 않는다. desktop/run-saved-batch.cjs는 실제 저장 자료 일괄 처리 스크립트이며 인자 형식은 현재 파일을 읽고 사용한다. 실행 명령을 추측해서 기존 결과를 덮어쓰지 않는다.

개발 의존성은 desktop/package-lock.json 기준 npm ci --prefix desktop으로 설치한다. 실제 일괄 처리 개발 명령은 desktop 폴더에서 npx electron run-saved-batch.cjs이며 사용자 입력과 현재 결과를 쓰므로 단순 문서 검증으로 반복 실행하지 않는다. smoke가 만드는 desktop/dist 프로필·예시 ZIP은 최종 배포와 분리하고 종료 전에 이번 실행의 임시 산출물을 정리한다.

주요 코드: desktop/main.cjs, preload.cjs, saved-materials.cjs, folder-batch.cjs, batch-input.cjs, batch-service.cjs, batch-catalog.cjs, source-access.cjs, public-source.cjs, atomic-file.cjs. 앱 쪽 source-batch*.js, source-page-plan.js, source-curation.js, source-bundle-zip.js, source-cut-*.js가 제작·조판·수동 편집과 연결된다. 이번은 문서 작업이며 이 코드들을 수정하지 않았다.

웹 운영 앱에는 Discovery, 검증, Source Package, 제작, 승인 Queue, 공식 Threads 게시/Insights, 실험 성과 기능이 있다. 외부 API 키/토큰의 현재 연결과 실제 게시 E2E는 이번 작업에서 확인하지 않았다. 키가 없으면 미설정/실패 상태를 유지한다. 예전 구현이나 테스트 더블을 실제 외부 게시 성공으로 표시하지 않는다.

## 15. 다른 대화/담당자에게 전달하는 방법

공유 대화 URL만 보내면 다른 AI가 본문을 읽지 못할 수 있다. 해당 공유 링크는 읽기 시 DisabledError가 있었고 링크 자체의 삭제/권한 문제로 확정하지 않았다. 다른 대화는 기존 PC·브라우저 로그인·파일 접근 권한을 자동으로 넘겨받는다고 가정하지 않는다.

새 대화에는 이 전체 인수인계 TXT와 인스타_레퍼런스_전체자료_2026-10-04.zip을 직접 첨부하고 GitHub 저장소 주소를 준다. 실제 PC를 수정해야 하면 기존 PC 연결과 원문 폴더 접근 가능 여부를 먼저 확인한다. 접근이 없으면 구현/자료 확보/실행 검증을 완료로 선언하지 않는다.

새 대화 시작 지시 예시:
“첨부 인수인계와 원본 ZIP을 읽고 kimjae134679/Threads의 현재 main을 확인해라. 구현된 기능과 제안 기능을 구분하고, 남은 우선순위의 실제 자료별 템플릿·의미별 장 구성·가독성 개선부터 진행해라. 기존 원본과 PhoneLoL 작업을 보존해라. 새 실행본과 대표 결과를 실제로 확인하고 저장소 인수인계와 허브 단일 스레드를 갱신해라. 자동 제작 완료를 검수·게시 완료로 표시하지 마라.”

## 16. 인수인계 갱신 규칙

각 의미 있는 작업이 끝나면 이 문서의 기준일, 실제 변경 파일, 코드/문서 commit, 데이터·결과 수, 실행한 검증과 미실행 검증, 산출물 경로, 미완료/보류, 다음 행동을 갱신한다. 허브 포인터는 현재 문서로 연결하고 THREAD.md에 같은 작업의 결과를 한 번 추가한다.

과거 테스트·오래된 수치·기획만 있는 기능을 최신 성공으로 재활용하지 않는다. 현재 문서가 실제 파일/코드와 다르면 실제 확인을 우선하고 문서를 수정한다. 원문 시각 불명은 null, 게시 여부 불명은 unknown이다. 최신 결과, 참고 기록, 원본을 구분하여 기록하며 공유 링크만을 유일한 인수인계로 사용하지 않는다.
