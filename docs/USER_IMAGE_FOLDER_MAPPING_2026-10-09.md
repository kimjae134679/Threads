# 사용자가 생성한 원본의 폴더 연결

사용자 저장 규칙은 `<자료 루트>/AI 생성 원본/<글 제목>/01.png`이다. 여러 장은 `02.png` 등으로 보관한다. 같은 폴더에 원문 링크와 프롬프트 텍스트를 보관한다. 그림 자체에는 제목을 넣지 않고 제목은 코드로 합성한다. 기존 원본을 덮어쓰거나 이미지 생성 작업을 실행하지 않는다.

이 폴더는 수동 인계 위치다. 폴더명만으로 글 ID나 제작버전을 추측하여 자동 교체하지 않는다. 파일이 도착하면 현재 제작 목록에서 글 ID·원문 URL·기존 출력버전을 확인하고, PNG의 실제 크기·바이트 수·SHA256과 프롬프트 SHA256을 계산한다. 확인하지 못한 모델·시각은 null로 둔다. 검토 계약의 장면 근거와 크롭·보호 영역도 확인해야 한다.

기존 지원 경로로 연결한다:

1. `threads-image-file-receive-v1.source.path`에 위 절대 PNG 경로를 지정한다. `source.transport.kind`는 `supported_local_file`이다. `postId`와 `requestId`를 명시한다.
2. `storageRoot`는 사용자 저장 폴더와 다른 전용 수신 루트다. 수신기는 글 ID·요청 ID·SHA를 기준으로 별도 보존하며 원본을 변경하지 않는다.
3. 검토된 `image-requirements.json`의 asset 파일·해시·프롬프트·도구 기록을 실제 수신 원본에 연결한다. 제목 폴더는 사람이 찾는 이름이며 계약의 `postId`가 연결 기준이다. 둘이 다르면 보류한다.
4. 단건 제작 요청의 `input`, `existingOutput`, `output`, `work`를 고정한다. 기존 본문 복사·해시 검증 후 별도 결과 폴더에 출력한다. 현재 결과로의 교체는 별도 승인된 범위에서만 한다.

수신 명령은 `node desktop/image-file-receive.cjs <수신 요청 JSON 절대 경로>`다. 기존 설치의 단건 합성 명령은 `Threads Cut Editor.exe --image-production-request=<단건 요청 JSON 절대 경로>`다. 수신기에 합성 실행을 맡길 때는 EXE 해시와 요청 JSON을 `compose`에 고정한다. 현재 수신기의 packaged runtime 검증은 `0.3.26`으로 고정돼 있으므로 `.27`을 연결해 실행하기 전에 이 검증 정책의 별도 조율이 필요하다. 수신만 하거나 검토 완료된 단건 제작 명령을 직접 실행하는 경로는 구분한다.

현재 원본 도착·SHA·글 ID·출력버전 확인이 없으므로 폴더 매핑은 준비 상태다. `ready` 또는 자동 연결 완료로 표시하지 않는다. 예약은 만들지 않는다. 단건 락·완료 체크포인트·실패 `held`를 기존 수신기와 제작기에서 사용한다. 작업 큐 전체를 갱신하지 않는다.
