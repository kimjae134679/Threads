# 원문 자료 ZIP 작성 가이드 — 제목·본문·이미지·댓글 선별

게시용 PNG를 만들기 전에 **원문 한 건당 원문 ZIP 한 개**를 만듭니다. 이 ZIP은 게시 이미지가 아닙니다. 실제 원본 파일과 “어디에서 무엇을 골랐는가”라는 근거를 묶어 전달하는 제작 입력입니다. 앱의 `원문 선별·이미지 제작` 화면이 같은 형식으로 ZIP을 저장하고 다시 읽습니다.

## 1. 수집 대상을 고른다

현재는 이미 쌓인 후보만 대상으로 합니다. 후보 파일의 정확한 개별 게시글 URL부터 확인하고, 주소만 있는 목록/검색 결과는 원문으로 쓰지 않습니다. 원문 페이지를 열 수 없다면 `원문 부족`으로 기록하고 다음 건으로 넘어갑니다. 로그인/접근 제한을 우회하지 않습니다.

원본 HTML 또는 직접 확인한 원문 TXT/JSON을 **바이트 그대로** 보관합니다. 첨부 이미지도 원본을 확보하고 파일명·해시를 남깁니다. 페이지의 로고·배너·광고·추천글·게시글 목록의 그림은 본문 이미지로 선택하지 않습니다. 사이트 전체를 훑어 저장한 이미지는 아직 본문 이미지가 아니라 후보 파일입니다.

## 2. 제목과 첫 장을 고른다

원문 제목은 그대로 적습니다. 첫 장의 큰 제목은 실제 제목/본문에서 근거를 찾을 수 있는 짧은 문장으로 별도로 씁니다. **근거 문장은 원문 제목이나 선택한 본문에서 실제 쓰인 문구를 그대로 인용**해 ZIP에 남깁니다. 과장해서 새 사실을 만들지 않습니다. **첫 장의 배경으로 사용할 원문 이미지 또는 원문 글 조각을 반드시 하나 지정**합니다. 이미지라면 원본 파일과 위치가 있어야 합니다. 글이라면 실제 본문 문장 일부가 배경에 보이도록 합니다. 단색 배경에 제목만 쓰는 첫 장은 제작하지 않습니다.

## 3. 본문을 순서대로 골라 표시한다

본문의 각 글 조각과 이미지를 원문에 나온 순서대로 기록합니다. 사용할 조각만 체크하고 원문 위치(HTML 경로 또는 TXT 글자 위치)를 남깁니다. 글 사이에 이미지가 있으면 바로 그 위치에 이미지가 와야 합니다. `본문`, `댓글`, `다른 게시글`, `광고`를 섞지 않습니다. 글자가 반복되거나 “게시글게시글/댓글댓글”처럼 UI가 섞였으면 원문과 대조해 정확한 본문 조각만 남깁니다. 대조가 안 되면 완료가 아니라 확인 필요입니다.

사람이 보기 좋은 장면 분할과 여백·의견 문구는 선별한 원문의 내용에 근거해 제작 단계에서 정합니다. 다른 사람의 댓글을 직접 쓴 의견처럼 표시하지 않습니다.

## 4. 댓글을 고른다

원문 페이지에서 실제 댓글 텍스트와 위치를 확인합니다. 사용할 댓글만 체크합니다. 좋아요 수 또는 BEST 표시가 화면에서 확인되면 근거를 함께 적습니다. 확인되지 않은 댓글을 새로 쓰거나, 좋아요 수가 없는 댓글을 “인기 댓글”이라고 부르지 않습니다. 댓글을 쓰지 않더라도 “확인했고 사용하지 않음”을 표시합니다. 아예 확인하지 못했으면 확인 완료를 체크하지 않습니다.

## 5. ZIP에 묶고 다시 읽어 확인한다

`http://127.0.0.1:4173/app/source-batch.html`에서 **기존 원문 모으기 → 해당 글의 원문 선별**을 누르거나, 로컬 **원본 폴더 선택 → 원본 선별 열기**를 사용합니다. 제목·본문 조각·원본 이미지·댓글·표지 배경을 고르고 대조 완료 상태를 체크한 뒤 **원본·선별 기준 ZIP 저장**을 누릅니다. ZIP을 재검토하려면 **기존 원문 ZIP 수정**을 사용하고, 완료된 ZIP은 **원문 ZIP에서 이미지 만들기**로 제작합니다.

원문 ZIP 형식 `threads-curated-source-v1`:

```text
bundle.json                 원문 제목/표지 제목, 선택 항목·원문 위치, 검토 표시, 파일 해시
raw/source.html              획득한 원본 HTML (TXT/JSON이면 원래 확장자)
raw/media/...                실제 선택한 원본 이미지 파일만
```

`bundle.json`은 체크한 본문/이미지/댓글 각각의 원문 위치를 보존합니다. 누락된 이미지, 비어 있는 본문, 배경으로 사용할 원문 조각의 부재, 본문·이미지·댓글 미확인을 발견하면 제작을 막습니다. ZIP을 열 때 원본과 이미지의 SHA-256을 다시 확인합니다. 외부 ZIP을 넣었거나 ZIP이 훼손됐으면 원본부터 다시 묶습니다. 생성된 게시용 ZIP에는 PNG와 제작 요약, 입력으로 쓴 원문 ZIP이 함께 들어갑니다.

## 한 건의 판정 표

| 요소 | ZIP에서 확인할 내용 | 없거나 불확실하면 |
| --- | --- | --- |
| 제목 | 실제 원문 제목, 첫 장 문구의 본문 근거 | 문구 재작성 또는 원문 확인 |
| 본문 | 사용할 정확한 문장·순서·원문 위치 | 이미지 제작 보류 |
| 이미지 | 실제 첨부 파일·해시·본문 내 위치 | 이미지 선택 해제 또는 원본 확보 |
| 댓글 | 실제 문구·위치, 인기라고 할 근거 | 사용하지 않음/확인 필요 명시 |
| 표지 배경 | 선택된 원문 이미지 또는 본문 글 조각 | 이미지 제작 보류 |

자료를 모았다는 것과 상업적 게시 권리를 확보했다는 것은 별개입니다. 제작 ZIP의 `publicationAllowed`는 항상 `false`입니다. 기존 검수 단계에서 별도로 결정합니다. 사용자 원문과 실제 편집 로그는 로컬에 보관하고 GitHub에는 업로드하지 않습니다.
