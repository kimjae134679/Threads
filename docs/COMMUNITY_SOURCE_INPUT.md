# 커뮤니티 원문을 프로그램에 넣는 방법

기준 확인: 2026-10-05 KST. 앱 0.3.5 / 제작 기준 2026-10-05.5.

앱은 저장 파일을 먼저 읽습니다. 원문이 없을 때만 기존 후보의 정확한 공개 주소를 보완합니다. 후보 요약인 content.txt·Jev 평가는 원문 전문으로 취급하지 않습니다.

| 사이트 | 읽기·입력 경로 | 자동 처리 |
|---|---|---|
| 더쿠·인벤·네이트판 | 기존 정확한 공개 글 주소에서 본문 HTML·연결 이미지 확보 | 공개 접근 가능한 기존 후보만 |
| 뽐뿌 | www의 정확한 공개 zboard/view.php?id=게시판&no=글번호 주소 | 기존 공개 후보만; 개인 게시판·검색 제외 |
| 블라인드 | 공개 웹의 글 존재 여부 확인. 내장 저장한 웹 글 가져오기로 원문 HTML·이미지 또는 원문 파일 입력 | 프로젝트에서 자동 수집 차단 |
| 디씨 | 공개 글은 정상 브라우저에서 읽고, 내장 저장한 웹 글 가져오기로 원문 HTML·이미지 입력 | 프로젝트에서 자동 수집 차단 |
| 여시 등 다음 카페 | 정상 로그인·가입·해당 게시판 등급을 갖춘 계정으로 읽기. 제공 권한이 있는 저장 자료 입력 | 회원 영역 자동 수집 차단 |

블라인드는 2026-05-18 시행 약관에서 사전 허락 없는 수집·복사·추출을 제한합니다. 앱은 계정·브라우저 쿠키를 복사하지 않습니다. 디씨의 공개 공지가 읽혔다는 사실과 자동 수집 허용은 별개입니다. 여시 회원 전용 글을 실제 로그인 세션으로 읽은 것으로 기록하지 않았습니다. 다음 검색에서 공개 글이 보이는 것과 카페 게시판 열람 권한도 별개입니다.

## 내장 가져오기

본문·이미지·인기 댓글이 표시된 페이지를 브라우저에서 Ctrl+S → 웹페이지 전체로 저장합니다. 앱의 `저장한 웹 글 가져오기`에서 HTML 파일을 선택하세요. 함께 저장된 같은 이름의 `_files` 폴더 또는 `media` 폴더의 실제 이미지를 가져옵니다. 최대 50개 원문 파일을 선택할 수 있고 기존 원문은 중복 등록하지 않습니다. 기존 원문을 덮어쓰는 기능은 아닙니다.

등록 뒤 `전체 이미지 만들기`로 일괄 처리합니다. 필요한 이미지나 댓글이 저장 파일에 없으면 만들어 채우지 않습니다. TXT/JSON은 아래 원문 형식으로 입력합니다. 동적 본문·댓글·영상은 Ctrl+S만으로 저장되지 않을 수 있으므로 파일을 직접 확인해야 합니다.

뽐뿌는 실제 공개 글 2건의 HTML·이미지를 확보했고 1건 제작·1건 안전한 분할 경계 부족 보류를 확인했습니다. 저장 HTML은 원래 인코딩의 원본 바이트를 원문 ZIP에 보존합니다. 모든 사이트·모바일 경로·접근 제한의 수집 성공을 뜻하지 않습니다.

## 한 글의 입력 폴더

원문 HTML 한 개와 같은 이름의 _files 폴더, 또는 source.txt/source.json과 media 폴더를 한 후보 폴더 안에 둡니다. 후보 폴더 또는 그 안 source 폴더에서 읽습니다. Chrome의 '웹페이지, 전체' 저장에서 생성되는 첨부 폴더도 읽습니다. 필요한 본문·이미지·댓글이 화면에 실제 표시된 뒤 저장해야 합니다. 동적 댓글·영상·로그인 상태가 HTML에 함께 저장된다고 보장하지 않습니다.

TXT:
```text
[TITLE]
실제 원문 제목
[BODY]
실제 본문을 그대로 붙여 넣습니다.
[IMAGE:photo1.jpg]
사진 바로 다음의 실제 본문
[COMMENTS]
[+123] 실제 확인한 댓글
```

이미지는 media/photo1.jpg에 둡니다. 댓글을 확보하지 못했다면 [COMMENTS] 아래를 비워 두십시오. 요약이나 추정 댓글을 넣지 않습니다.

JSON은 schema=threads-verbatim-source-v1, verbatim=true, title, body, comments 배열을 사용합니다. 이미지 위치는 body의 [IMAGE:파일명] 행입니다. 원문 전체가 없는 자료에 verbatim=true를 쓰지 않습니다.

## 수집부터 계획·제작까지

1. 수집 전에 작업 정보/capture-plan.json에 적용할 제목·배치·이미지·댓글 규칙과 기준 버전을 기록합니다.
2. 원문 확보 뒤 장별 좌표·크기·사용 조각·표지 문구·제외 사유를 production-plan.json과 제작 계획.md에 저장합니다.
3. 저장한 계획과 원문 ZIP 해시가 같을 때 그 계획으로 PNG를 그립니다.
4. 자료 안내.txt, 앱 목록, status.csv에 제작일·기준 버전·보류 이유를 표시합니다. 출력 완료는 검수 완료 또는 게시 완료를 뜻하지 않습니다.
5. 게시 상태는 workflow-state.json의 명시적인 게시 URL·시각 기록으로만 판단합니다. 기록이 없으면 '확인 기록 없음'입니다. 외부 게시를 추정해 완료 처리하지 않습니다.
