# 30-Day Execution Plan

목표는 30일 안에 `어떤 소재 × 어떤 포맷 × 어떤 플랫폼`이 실제 반응과 수익 가능성이 있는지 검증하는 것이다. 처음부터 완전 자동화 시스템을 만들지 않는다.

## 시작 계정 구조

한 계정에 모든 주제를 섞기보다 **콘텐츠 축을 분리**한다. 엔진/리서치 데이터는 공유하되 채널 정체성은 나눈다.

### Track A — Hot / Issue

- 오늘 화제
- 신제품/AI/인터넷 이슈
- 왜 뜨는지 설명
- 쟁점/찬반 정리
- 후속 전망

추천 플랫폼: Threads → Shorts/Reels → YouTube/Blog

### Track B — Internet Story / Community Culture

- 온라인에서 화제가 된 사연의 **재구성**
- 인터넷 문화/밈의 배경 설명
- 댓글에서 갈리는 논리 정리
- 일반인 식별정보 제거

추천 플랫폼: Threads + Reels/Shorts

주의: 원문 캡처/댓글 복붙 계정으로 만들지 않는다.

### Track C — Useful / Money / Product

- 유용한 서비스/앱/AI 도구
- 가격/기능 비교
- 할인/신제품/실사용 팁
- 검색 수요가 있는 설명형 콘텐츠

추천 플랫폼: Blog + YouTube + Threads

이 Track은 향후 affiliate/brand 수익과 연결하기 쉽다.

처음에는 **A + B**를 빠른 바이럴 실험축, **C**를 수익 전환 실험축으로 본다.

# Week 1 — 수동으로 시장 감 잡기

## 해야 할 것

매일 후보 15~30개를 모으되 실제 게시물은 3~6개만 만든다.

후보마다:

```text
source
why_now
trend_score
rights_risk
one_sentence_angle
best_platform
revenue_path
```

를 기록한다.

## 게시 실험

### Threads
- 하루 2~4개
- 같은 소재로 훅 2종을 만들어 어느 쪽이 반응이 나오는지 기록
- 단순 링크 포스트보다 자체 요약/관점 중심

### Shorts / Reels
- 하루 1개 또는 이틀 1개
- 20~60초
- 같은 영상 파일을 무작정 워터마크 포함 재업로드하지 않고 플랫폼별 캡션/훅을 조정

### Blog
- 주 2~3개
- Shorts에서 반응한 소재 중 검색형으로 확장 가능한 것만 작성

## 이번 주 목표

- 조회수 높은 주제가 아니라 **반복해서 반응하는 주제 패턴** 찾기
- 작업 1건당 실제 소요시간 측정
- 저작권/검증 때문에 버린 후보 비율 기록

# Week 2 — AI 편집 파이프라인 고정

AI가 자동으로 할 일:

1. 링크/메모 정리
2. 같은 사건 중복 묶기
3. 공식/복수 출처 검색
4. 확인 사실 / 미확인 주장 분리
5. 가능한 콘텐츠 각도 3개 제안
6. 플랫폼별 초안 생성
7. 위험 플래그 생성
8. 게시 후 성과 요약

사람이 할 일:

- 어떤 후보를 실제 제작할지 선택
- 사실/권리 위험 확인
- 최종 말투/훅 수정
- 고위험 소재 승인
- X 수익계정 직접 게시

## 템플릿화하면 안 되는 것

- 매 영상 똑같은 AI 음성 + 똑같은 B-roll + 명사만 교체
- 같은 이야기 구조를 수십 번 복제
- 원문 문장을 순서만 바꿔 재작성

YouTube의 2025~2026 수익화 정책상 이런 구조는 `mass-produced / inauthentic` 위험이 크다.

# Week 3 — 멀티포맷 재활용 실험

한 Topic으로 최대 5개 결과물을 만든다.

```text
Topic
├─ Threads: 5~10문장
├─ Instagram Carousel: 6~8장
├─ Short Video: 30~60초
├─ Blog: 800~1,500자+ / 필요 깊이에 따라 확장
└─ YouTube Long: 반응 검증된 주제만 5~10분
```

같은 문장을 복붙하는 것이 아니라 플랫폼 목적에 맞게 바꾼다.

### 예시

소재: 새 AI 서비스 공개

Threads:
- “이게 왜 갑자기 화제인지”

Shorts:
- 실제 차이 3개를 빠르게 보여줌

Carousel:
- 이전 방식 vs 새 방식 비교

Blog:
- 가격/기능/사용법/누구에게 맞는지

Long-form:
- 직접 테스트 + 경쟁 서비스 비교

# Week 4 — 수익 가능성 판정

콘텐츠를 조회수만으로 평가하지 않는다.

## KPI

### Attention
- impressions/views
- 3초/완시율/평균시청
- scroll stop / hook performance

### Engagement
- likes
- replies/comments
- shares
- saves/bookmarks

### Audience
- profile visits
- follows per 1,000 views
- returning viewers

### Conversion
- link clicks
- affiliate clicks
- affiliate revenue
- newsletter/site visits
- inquiry/brand contact

### Efficiency
- 제작 시간
- AI 비용
- 영상 생성 비용
- 1,000 view당 제작비
- 1 follow당 제작비
- 1 click당 제작비

## 30일 후 Kill / Keep / Scale

각 `Track × Format × Platform`에 대해:

```text
SCALE = 반응 + 반복가능성 + 수익 연결이 모두 좋음
KEEP  = 반응은 있지만 데이터 더 필요
KILL  = 제작비/리스크 대비 성과가 지속적으로 낮음
```

잘 안 되는 축은 미련 없이 줄이고, 상위 20~30% 조합에 제작량을 몰아준다.

# 자동화 단계

## Stage 0
수동 링크 → AI 초안 → 사람이 게시

## Stage 1
허용 소스 자동 탐색 → AI 점수 → 사람이 선택

## Stage 2
AI가 Research Bundle + 3~5 포맷 생성 → 사람이 승인

## Stage 3
공식 API로 승인된 콘텐츠 예약 게시 + 성과 수집

## Stage 4
성과 데이터로 후보 점수와 포맷 추천 자동 조정

## Stage 5
저위험 콘텐츠만 제한적 자동승인

**Stage 5는 초기에 하지 않는다.**

# 당장 만들지 않을 것

- DCInside/Blind 자동 크롤러
- 여러 커뮤니티 로그인 우회 수집기
- 타인 Shorts/Reels 다운로드 후 자동 재업로드기

- X Original Content Rewards용 자동게시 봇

이들은 정책/권리 리스크가 높거나 장기 수익화에 불리하다.

# 첫 번째 실제 성공 기준

프로그램의 첫 성공은 `자동으로 100개 게시`가 아니다.

다음이 한 번 완주되면 MVP 성공으로 본다.

```text
허용 소스에서 후보 발견
→ 같은 사건 3개 출처 묶음
→ 사실 검증
→ 권리/위험 판정
→ Threads + Short + Blog 초안 생성
→ 사람 승인
→ 게시
→ 24/72시간 성과 회수
→ 다음 추천에 반영
```

이 흐름을 안정화한 뒤 게시량을 늘린다.
