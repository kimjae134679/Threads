# 글별 실사 밀착 AI 이미지 제작 기준

기록일: 2026-10-09 KST. 역할: `03_PRODUCTION`. 현재 채팅에서 사용자가 정정하고 승인한 이미지 스타일과 저장 방식을 기록한다. 이전의 그림체·넓은 구도보다 이 기준을 우선한다.

## 사용자 승인 기준

| 항목 | 적용 기준 |
|---|---|
| 비율 | 정사각형 **1:1**. 저장한 PNG의 실제 가로·세로가 같은지 확인한다. 특정 픽셀 수를 생성 성공만으로 가정하지 않는다. |
| 스타일 | **실물 사람을 카메라로 촬영한 것 같은 실사 사진**. 자연스러운 피부·표정·빛·질감을 사용하며 그림체·만화·일러스트 느낌을 쓰지 않는다. |
| 구도 | **가까이, 화면을 꽉 채운 밀착 클로즈업**. 여유로운 원경·전신·넓은 배경·큰 빈 여백을 피한다. 아래에 합성할 제목에 가리지 않도록 핵심 정보는 상단 중심에 배치하고, 하단은 비핵심 몸통·옷·흐린 배경으로 자연스럽게 채운다. |
| 핵심 정보 | 얼굴만 크게 확대하지 않는다. **핵심 행동·소품과 인물 표정**이 함께 보여 글의 상황을 이해할 수 있어야 한다. 주요 피사체·표정·핵심 소품이 화면 대부분을 차지하도록 하고, 인물 비율을 왜곡하지 말고 카메라가 가까워진 느낌으로 구성한다. 음식·사물·단체가 중심인 글을 억지로 한 사람의 얼굴 확대 장면으로 바꾸지 않는다. |
| 제목과 피사체 위치 | 사용자는 **“글씨를 아래에 적을 거라 얼굴 등이 아래쪽에 있어 가려지면 안 된다”**고 추가 요청했다. 얼굴 전체(눈·입·턱), 표정, 핵심 행동·의미 있는 소품을 상단 중심으로 올린다. 아기 얼굴이나 음식·사물 중심 글의 핵심 피사체도 제목 아래에 숨지 않게 한다. |
| 내용 적합성 | 제목만 보고 추정하지 않고 글 전체와 필요한 원문 이미지를 확인한다. 차분한 정물의 반복 대신 해당 소재의 상황·표정·갈등을 적당히 표현한다. 원문에 없는 사건·폭력·반응을 추가하지 않는다. |
| 진행 | **한 글 확인 → 한 장 생성 → 실제 이미지 확인 → 즉시 저장·기록 → 다음 글**. 여러 글을 병렬 생성하거나 생성한 이미지를 저장하지 않은 채 다음으로 넘어가지 않는다. |

사용자의 “느낌좋네”는 **실사·밀착 스타일에 대한 승인**이다. 모든 글의 개별 이미지 품질 승인이나 실제 게시 승인으로 확대하지 않는다.

## 제작 단계와 인계 — 2026-10-10 추가

사용자가 정한 순서는 **자료 수집·정리 → 이미지 제작 → 실제 게시 이미지 생성 → 검토 → 게시 예약**이다. 현재 이미지 담당의 산출물은 후단 프로그램이 합성할 수 있는 **무문자 원본**이며, 이 원본 자체를 최종 게시 이미지로 처리하지 않는다. 역할별 소유권과 기존 입력 계약은 [운영 인계 규칙](HANDOFF_CONTRACTS.md#수집이미지합성-운영-인계--2026-10-10-사용자-지시)을 따른다.

- 수집 담당이 고정 글 ID·원문·출처·권리·분류와 **표시용 제목 / 인스타 전체 문안 / 쓰레드 표지 제목 / 공용·주제별 해시태그**를 준비·관리한다. 표시용 제목의 네이트판·게시판명·불필요한 분류 표기는 정리하되 원문 제목·내용·출처는 보존한다. 이미지 담당이 이 자료를 임의 재작성하거나 사실·권리 확인을 대신하지 않는다.
- 이미지 담당은 **수집 담당의 같은 고정 글 ID**에 연결하여 원본 PNG·프롬프트·생성 기록과 실제 파일 위치·SHA-256·크기·선택 버전·이전 버전 관계를 넘긴다. 기존 임시 URL 해시 ID는 공식 ID가 아니다. 공식 ID 연결이 미확정이면 원본과 임시 기록을 보존하고 프로그램 자동 투입을 보류한다. 기존 코드의 `sourceId`를 고정 글 ID로 단정하지 않는다.
- 후단 프로그램은 기존 `threads-cover-asset-v1` 계약을 재사용하여 별도 제목 합성에 원본을 사용할 수 있다. 원본·이전 시안은 덮어쓰지 않으며, 합성 결과와 그 결과의 `outputVersion`은 원본 자산 버전과 구분한다. 새 입력 schema나 앱 기능이 구현되었다고 기록하지 않는다.
- 하단 제목에 대비해 얼굴·핵심 행동·소품을 상단에 둔다. 원본 구도 확인 다음에는 **실제 합성 제목을 올린 결과의 가림·가독성 검토**가 별도로 필요하다. 원본 생성·저장 ≠ 제목 합성 검수 ≠ 사람 승인 ≠ 예약·게시다. 현재 요청만으로 실제 예약이나 게시를 실행하지 않는다.

## 하단 제목 오버레이 안전 영역 — 2026-10-09 추가

- 사용자 직접 조건은 **아래에 넣는 글씨가 얼굴·핵심 정보를 가리지 않는 것**이다. 구현을 위한 **운영 기본값**으로 이미지 하단 약 **40%**를 제목 오버레이 안전 영역으로 잡는다. 40% 자체는 사용자가 정한 정량 기준이 아니다.
- 안전 영역에는 얼굴 전체나 아기 얼굴, 감정을 읽는 눈·입·턱, 핵심 손동작과 의미 있는 소품을 두지 않는다. 인물·단체·음식·사물 모두 글을 이해하는 데 필요한 정보가 제목 위에 남아야 한다.
- 실제 긴 제목이나 여러 줄 제목이 안전 영역 경계보다 높이 올라오면, 핵심 피사체를 그 제목 상단보다 **여유 있게 더 위로** 배치한다. 구도 확인은 숫자 경계만이 아니라 실제 제목이 덮을 범위를 기준으로 한다.
- 이는 넓은 빈 공간이나 느슨한 원경을 만들라는 뜻이 아니다. 실사·꽉 찬 밀착 구도를 유지하면서 아래에는 옷·비핵심 몸통·자연스럽게 흐린 배경을 채우고, 핵심 얼굴과 행동·소품은 위에서 충분히 크게 보여준다.
- AI 원본에는 제목 글자를 직접 생성하지 않는다. 제목은 별도 합성하며 아래 [입력과 출력](#입력과-출력)의 무문자 원본 운영 방식을 유지한다.
- 이번 추가는 **현재 진행 목록의 267번째부터 새로 만드는 이미지**에 적용한다. 기존 저장 이미지의 일괄 재제작, 앱 표지 레이아웃 변경, 기존 원본 교체는 요청 범위가 아니다. 개별 재작업은 별도 지시가 있을 때 수행한다.
- 저장 전 시각 확인에서 얼굴이 잘리지 않았는지, 핵심 행동·소품이 제목 범위에 가려질 위치인지 함께 확인한다. 생성·저장 성공은 실제 제목 합성 검수나 사용자 품질 승인과 구분한다.

## 입력과 출력

- 입력: `D:\A_KJ\AI\Projects\Threads\자료\06_자동 제작 결과\현재 결과`
- 출력: `D:\A_KJ\AI\Projects\Threads\자료\AI 생성 원본\<글 제목>`
- 입력의 `production-plan.json`에 있는 원문 `sourceUnits`·글 ID·출처와 필요한 원문 이미지/묶음을 읽는다. 렌더된 장만으로 빠진 문장을 추측하지 않는다.
- Windows 파일명에 사용할 수 없는 문자만 안전하게 바꾸고, 원제와 글 ID의 연결은 생성 기록에 보존한다. 같은 제목이 충돌하면 기존 폴더를 덮어쓰지 말고 글 ID로 구분한다.
- 기존 원문·제작 결과·평가·실패/이전 시안은 보존한다. 생성 결과를 원문 사진이나 검증된 증거로 바꾸지 않는다.
- **운영 기본값**은 글자·캡션·로고·워터마크 없는 상황 이미지다. 이는 사용자가 직접 정한 스타일 조건과 구분하며, 원본 이미지와 별도 제목 합성을 분리하기 위한 방식이다. 기존 제작본에 자동 삽입하지 않는다.

글 제목 폴더에는 다음을 함께 저장한다.

1. 실제 생성된 **PNG**. 수정본은 새 버전 파일로 저장한다.
2. **생성 프롬프트 TXT**. 실제 사용한 요청을 보존하고, 요약·복원 설명이면 그 사실을 표시한다.
3. **생성 기록 JSON**: 원제, 글 ID, 입력/출력 경로, 출처 URL·원문 해시, 생성 시각·방법, 사용 프롬프트, 소재 관련성, 실제 PNG 크기·SHA-256, 시각 확인 범위, 이전 버전, 사용자 승인·게시 상태.

생성 기록에는 **“AI로 생성한 가상 상황 이미지입니다. 실제 사건 현장이나 당사자 사진이 아닙니다.”**를 명시한다. 실제 사람의 신원이나 현장 사진이라고 주장하지 않는다. 개인정보·권리·사실 검증과 [사람 검수 전달 규칙](HANDOFF_CONTRACTS.md)은 계속 적용한다.

전체 진행은 출력 루트의 `00_생성 진행.json`에서 실제 저장된 항목만 생성 완료로 기록한다. 파일·해시·크기 확인과 시각 확인, 사용자 품질 승인, 게시 승인은 서로 다른 상태다. 공개 GitHub에는 기준 문서만 올리며 원문 전문·생성 원본 PNG·개별 결과 데이터는 올리지 않는다.

## 장면을 정하는 원칙

- 갈등 사연은 원문 `sourceUnits`에 실제 있는 내용·시점을 선택하고 인물 간 거리·표정·손동작과 핵심 소품으로 표현한다. 원문에 없는 경찰·체포 등 사건·역할, 조롱·폭력·추가 혐의를 만들지 않는다.
- 음식 사연도 갈등이나 행동이 핵심이면 음식 정물만 보여주지 않는다. 글에 맞는 행동과 음식/용기를 함께 가까이 보여준다.
- 돈·주거 사연은 계약·열쇠 등 맥락을 보조하되 가짜 금액 문서나 보장 수익의 증거를 만들지 않는다.
- 원문이 사진·도표·캡처 중심이고 내용을 아직 읽지 못했다면 제목만으로 생성하지 않고 본문 확인 대기로 남긴다.

## 기록 시점의 진행 범위

2026-10-09 현재 순차 생성·저장 작업은 진행 중이다. 이 문서는 전체 이미지 제작 완료·전체 글의 품질 승인·게시를 의미하지 않는다. 완료 수량을 이 기준 문서에 고정하지 않고 로컬 진행 JSON과 실제 저장 파일을 대조해 확인한다.

이번 GitHub 반영은 제작 기준 문서화이며 앱 코드·기존 표지·본문·평가를 변경하거나 이미지를 추가 생성하는 작업이 아니다. 기존 [표지 취향](USER_COVER_PREFERENCES_2026-10-05.md)과 [제작 기반](POST_PRODUCTION_FOUNDATION_2026-10-06.md)은 유지하며, 새 AI 원본 제작의 실사·구도·순차 저장에는 이 최신 기준을 적용한다.
