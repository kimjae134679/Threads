# 이미지 필수 제작과 묶음별 리뷰

최신 사용자 범위는 유효한 사용자 AI 원본 대응 글만 제작·현재 결과에 노출하는 것이다. 실제 ID·제목·생성 기록 SHA·원본 PNG SHA·크기를 재검증한 현재 결과는 199개다. 이미지 없는 166개는 `자료/05_이전 작업/표지 개별 수정/installed-fullbleed-20261009/이미지 없는 제작물 보관`으로 옮기고 제작 대기 행으로 유지했다. 원문, 본문, 사용자 이미지 원본, 평가, 검토 회차는 보존했다.

현재 표지는 실제 설치 프로그램 `0.3.33-cover.20261009.7`로 199개 전부 다시 렌더한 뒤 현재 결과로 교체했다. 설치 소스 커밋은 `1644d63c8491a8267dd535c26dcebc9e66d2b5a3`, app.asar SHA256은 `62a66cb5650e81a3e4346acadacc1306d33629968b5369f5e6af112157ecf788`다. 실제 감사에서 유효 AI 출력 199개, 이미지 없는 출력 0개, 표지/본문 1080px 로딩, 평가/진행 파일 바이트 보존을 확인했다. 전 대상의 원본 ZIP·AI 원본·본문 1,520장과 이전 결과 전체 파일 해시를 확인했다. 이미지 없는 166개와 기존 과거 자료는 그대로 보존했다.

이전 .6 표지 199개는 `자료/05_이전 작업/표지 개별 수정/title-local-shade-20261009-pixel-center`에 복구 가능하게 보관했다. .32 중간 검증에서 짧은 그라데이션 전환 구간의 픽셀 경계/중심 차이로 13건이 held 처리됐으며 현재 결과에 등록하지 않았다. 픽셀 중심(y+0.5)에 맞춘 .33 검사에서 전체199건이 통과했다. 허용 오차를 넓히거나 원본 이미지를 바꾸지 않았다.

현재 묶음은 `production-1c7416cf-f165-4552-97a0-32eed47c8b1d`, 제작 2차다. 현재 status에는 새 묶음만 등록하고 거절된 이전 스타일은 보관 위치에 유지한다. 행의 `id`는 원본 글, `outputVersion`은 실제 제작물, `productionBatch.id`는 제작 실행을 구분한다. 후속 실행은 `work/production-batch.json`에 한 번 저장한 ID·차수·시작 시각·request SHA를 재개 시 그대로 사용한다. 새 요청에는 별도 work를 사용한다. 등록 담당은 checkpoint의 `changed.productionBatch`를 status에 보존한다. 배치 ID가 fingerprint에 포함되어 새 실행의 평가/열람이 이전 버전과 섞이지 않는다. 등록까지 한 실행을 완료한 뒤 다음 실행을 시작해 차수 배정을 직렬화한다.

프로그램 시작은 묶음별 카드 뷰어다. 최신 묶음은 기본 펼침, 이전 묶음은 기본 접힘이며 검색 전에 차수를 계산한다. 카드의 평가하기는 동일 글·묶음·버전으로 들어간다. 뷰어로 돌아가기는 저장 큐·열람 큐가 끝난 뒤 이동하고 실패하면 평가 화면과 메모를 유지한다. 두 테스트 묶음에서 스크롤 250px, 선택 카드, 펼침 상태, 저장된 메모 복원을 확인했다. 저장 실패 주입도 실제 자료 사본에서 확인했다. 검증용 메모는 실제 자료에 기록하지 않았다.

예약 담당의 ready gate: 원문/글 ID/제목 일치 → 활성 AI 생성 기록과 원본 해시 확인 → 별도 output/work → 실제 현재 oldRow 일치 → 실행 잠금 없음 → 한 글 제작 → complete checkpoint 및 actual packaged runtime 확인 → 원문·본문 해시 확인 → canonical writer로 등록 → 실제 저장소 표지/본문 읽기 성공 → 다음 글. 이미지가 없거나 잠금/해시/버전/렌더 오류가 있으면 held로 보류하고 현재 결과를 바꾸지 않는다. 중복 작업은 동일 work와 request를 유지하고 잠금을 삭제하지 않는다.

한 글 명령:

```powershell
& '.\scripts\이미지 있는 한 글 제작.ps1' -요청파일 'C:\작업\한글요청.json'
```

요청 형식은 `threads-existing-cover-reproduction-v1`, 절대 `sourceRoot/output/work`, 기존 `reviewRound`, 한 행의 `id/title/oldRow/titleStyle/generatedCover`다. generatedCover는 `recordPath/generationRecordSha256/fileSha256`를 요구한다. 프로그램이 실제 원본 소비를 검증하며 이미지가 없으면 캐시 완료나 글씨형 제작으로 우회하지 않는다. 이 명령은 기존 승인된 현재 표지의 별도 출력까지 수행한다. 현재 결과 등록, 이미지 없는 대기 글의 최초 제작, 일반 source-batch 전체 경로, 동일 글 과거 배치 탐색, 업로드 및 예약 생성은 별도 담당 범위다.

빈 canonical lock은 실패한 검증 프로세스 시작과 같은 시각에 남았다. 실행 소유자·열린 핸들이 없고 파일이 바뀌지 않았음을 확인한 뒤 원본을 복구 보관했다. 자동 강제 삭제를 추가하지 않았다. 감사 프로세스는 종료까지 기다리며 격리 프로필을 사용한다. 실제 사용자 창 포커스는 Windows가 거절해 이전 창을 강제로 닫지 않았다.
