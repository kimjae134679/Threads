# 이미지 필수 제작과 묶음별 리뷰

최신 사용자 범위는 유효한 사용자 AI 원본 대응 글만 제작·현재 결과에 노출하는 것이다. 실제 ID·제목·생성 기록 SHA·원본 PNG SHA·크기를 재검증한 현재 결과는 199개다. 이미지 없는 166개는 `자료/05_이전 작업/표지 개별 수정/installed-fullbleed-20261009/이미지 없는 제작물 보관`으로 옮기고 제작 대기 행으로 유지했다. 원문, 본문, 사용자 이미지 원본, 평가, 검토 회차는 보존했다.

현재 표지는 실제 설치 프로그램 `0.3.34-cover.20261009.8`로199개 전부 다시 렌더한 뒤 현재 결과로 교체했다. 제작 소스 커밋은 `27ec7ff5816e4fc8792611f32d33d961e7d89fb9`, app.asar SHA256은 `2e5e6113b81de60c97fa3418596ee9907cb4e4e7a69a004da49089d34005ae4e`다. 유효 AI 출력199개, 이미지 없는 출력0개이며 원본 ZIP·AI 원본·본문1,520장과 이전 결과 전체 파일 해시를 확인했다. 이미지 없는166개와 기존 과거 자료는 그대로 보존했다. 하단 fade-out을 없애85% 어둠이 맨 아래까지 유지되며 위쪽 전환은 길고 부드럽게 이어진다.

현재 리뷰 진입점은 `0.3.35-cover.20261009.8`이다. 설치 소스 커밋은 `001c2897c6bd8f6c5cb325d31942220e2785003a`, app.asar SHA256은 `4fb1adfb69b7356fb61697fc86e08b9b29547d347ff5fac52c9e511135eadebc`다. .35는 전체 본문 감사 대상만 실제 갤러리에 표시되는 글로 보완했으며 .34와 실제 표지 렌더4모듈·타이포그래피·폰트가 동일하다. 설치 읽기 전용 감사에서 유효 이미지199개, 표지/본문1080px, 실제 카드 진입→아래로 읽기→19장 전부 로딩→뷰어 복귀, 평가/진행 파일 바이트 보존을 확인했다.

이전 .7 표지199개는 `자료/05_이전 작업/표지 개별 수정/smooth-bottom-gradient-20261009`에 복구 가능하게 보관했다. 앞선 .32 측정 실패나 .7 완료 기록을 이번 .8 처리 수로 사용하지 않았다. 현재 묶음은 `production-2332e967-2c2f-463d-9530-7d2e7b53b334`, 제작3차다. 현재 status에는 새 묶음만 등록하고 거절된 이전 스타일은 보관 위치에 유지한다. 행의 id는 원본 글, outputVersion은 제작물, productionBatch.id는 제작 실행을 구분한다. 같은 request/work의 재개는 같은 배치를 유지하며 새 요청에는 별도 work를 사용한다. 등록 담당은 checkpoint의 changed.productionBatch를 status에 보존한다. 한 실행의 등록을 마친 뒤 다음 실행을 시작해 차수 배정을 직렬화한다.

프로그램 시작은 묶음별 카드 뷰어다. 최신 묶음은 기본 펼침, 이전 묶음은 기본 접힘이며 검색 전에 차수를 계산한다. 카드의 평가하기는 동일 글·묶음·버전으로 들어간다. 뷰어로 돌아가기는 저장 큐·열람 큐가 끝난 뒤 이동하고 실패하면 평가 화면과 메모를 유지한다. 두 테스트 묶음에서 스크롤 250px, 선택 카드, 펼침 상태, 저장된 메모 복원을 확인했다. 저장 실패 주입도 실제 자료 사본에서 확인했다. 검증용 메모는 실제 자료에 기록하지 않았다.

예약 담당의 ready gate: 원문/글 ID/제목 일치 → 활성 AI 생성 기록과 원본 해시 확인 → 별도 output/work → 실제 현재 oldRow 일치 → 실행 잠금 없음 → 한 글 제작 → complete checkpoint 및 actual packaged runtime 확인 → 원문·본문 해시 확인 → canonical writer로 등록 → 실제 저장소 표지/본문 읽기 성공 → 다음 글. 이미지가 없거나 잠금/해시/버전/렌더 오류가 있으면 held로 보류하고 현재 결과를 바꾸지 않는다. 중복 작업은 동일 work와 request를 유지하고 잠금을 삭제하지 않는다.

한 글 명령:

```powershell
& '.\scripts\이미지 있는 한 글 제작.ps1' -요청파일 'C:\작업\한글요청.json'
```

요청 형식은 `threads-existing-cover-reproduction-v1`, 절대 `sourceRoot/output/work`, 기존 `reviewRound`, 한 행의 `id/title/oldRow/titleStyle/generatedCover`다. generatedCover는 `recordPath/generationRecordSha256/fileSha256`를 요구한다. 프로그램이 실제 원본 소비를 검증하며 이미지가 없으면 캐시 완료나 글씨형 제작으로 우회하지 않는다. 이 명령은 기존 승인된 현재 표지의 별도 출력까지 수행한다. 현재 결과 등록, 이미지 없는 대기 글의 최초 제작, 일반 source-batch 전체 경로, 동일 글 과거 배치 탐색, 업로드 및 예약 생성은 별도 담당 범위다.

빈 canonical lock은 실패한 검증 프로세스 시작과 같은 시각에 남았다. 실행 소유자·열린 핸들이 없고 파일이 바뀌지 않았음을 확인한 뒤 원본을 복구 보관했다. 자동 강제 삭제를 추가하지 않았다. 감사 프로세스는 종료까지 기다리며 격리 프로필을 사용한다. 실제 사용자 창 포커스는 Windows가 거절해 이전 창을 강제로 닫지 않았다.

전체 본문을 보는 방법: 자료/프로그램 실행.lnk를 열거나 최신 표지 그리드의 게시글 리뷰 열기 진입점을 사용한다. 프로그램 카드의 평가하기를 누른 뒤 아래로 읽기로 전체 본문·댓글을 이어서 본다. 한 장씩 넘기기와 좌우 화살표도 유지한다. 뷰어로 돌아가기로 목록에 복귀한다. 웹 그리드의 표지 이미지는 PNG 확대 링크다. 파일 브라우저의 바로가기 실행 정책에 따라 웹 링크가 열리지 않으면 자료/프로그램 실행.lnk를 직접 연다. 링크 파일과 대상 경로는 검증했으나 브라우저 클릭 자체는 연결 도구가 끊겨 확인하지 못했다.
