# 이미지 필수 제작과 묶음별 리뷰

현재 사용자 AI 원본 대응 표지는199개이고 대응 이미지 없는166개는 제작 대기다. 원문·본문·사용자 이미지 원본·평가·같은 리뷰 회차를 보존했다. 이미지 없는 과거 제작물은 자료/05_이전 작업/표지 개별 수정/installed-fullbleed-20261009/이미지 없는 제작물 보관에 있다.

199개 모두 `.36` 설치본에서 승인된 `.6` 큰 제목 배치와70% 하단 음영으로 실제 재제작한 뒤, 출처 태그가 남은23개만 `.37` 설치본에서 정제 제목으로 다시 출력했다. 나머지176개 출력 버전과 이미지 해시는 유지했다. 현재 표지 레시피는 fullbleed + SB_Aggro_B + 제목 전체 + 제한된2색 + title-legacy-geometry-shade70-v1이다. 대응 자산·생성 기록·원문 ZIP·본문/댓글1,520장은 보존했다.

최종 리뷰 및 향후 한 글 제작 진입점은 `0.3.38-cover.20261009.10`이다. 설치 소스는 `dd0bed6763780314a12941d25e1e835d1b67d693`, app.asar SHA256은 `e1f9671cb83f4dbdf6b52a65cef5776c10098fae034340733f1248fc21475fd1`이다. 실제 설치 검수에서 유효 이미지199개, 표지/본문1080px, 카드 진입→아래로 읽기→19장 전부 로딩→뷰어 복귀, 선택 유지 및 평가/진행 바이트 보존을 확인했다. 리뷰 UI5개 파일과 서비스/검수 모듈은 이전 `.35`와 같다.

현재 묶음은 제작4차199개 중 유지된176개와 제작5차 태그 정제23개다. 4차 ID는 `production-f169f5b0-d111-40fc-af1c-78789cf0a4c3`, 5차 ID는 `production-944c0f0d-707d-4df5-9440-3f5d07ed19f5`다. id는 원문 글, outputVersion은 제작물, productionBatch.id는 제작 실행을 구분한다. 같은 request/work 재개는 같은 배치를 유지하고 새 요청은 별도 work를 사용한다. 등록 담당은 checkpoint.changed.productionBatch를 status에 보존한다. 한 실행 등록을 끝낸 뒤 다음 실행을 시작해 차수를 직렬 배정한다.

입력 정리는 원문 가져오기·후보 읽기·정확한 원문/HTML/저장 이미지 초안 단계부터 originalTitle/sourceUrl을 보존하고 displayTitle/captionInputTitle을 확정한다. 기존199개 준비자료에는 작업 정보/title-input.json과 title-input-index.json을 파생 계약으로 저장했다. 원본 입력596개 파일의 해시와 현재 출력 버전199개가 유지됐다. 태그가 포함된 원문 제목은 내부 근거와 자산 대응에 사용하며, 표시·표지·캡션 제작에는 정제 제목을 소비한다. 일반 단어 판, 설명 괄호, 사용자 캡션 제목 형식 `[ 깨끗한 제목 ]`은 보존한다. 정제 계약이 원문·출처와 다르면 보류하며 최종 렌더 검사도 유지한다.

프로그램 시작은 묶음별 카드 뷰어다. 최신 묶음은 기본 펼침, 이전 묶음은 기본 접힘이며 검색 전에 차수를 계산한다. 카드의 평가하기는 동일 글·묶음·버전으로 들어간다. 뷰어 복귀는 저장/열람 큐가 끝난 뒤 이동하고 실패하면 평가 화면과 메모를 유지한다. 실제 점수나 검토 메모를 검증 목적으로 만들지 않는다.

## 부모 예약 담당에게 넘기는 한 글 계약

이 작업에서 예약을 만들거나 변경하지 않았다. 예약 작업명은 `표지 이미지 계획 확인 — <글ID>`이고 한 번에 한 글을 처리한다. 기존 열람/보류 이력과 현재 회차를 먼저 확인하여 이미 본 소재를 새 미리뷰 소재로 다시 공급하지 않는다.

ready gate: 원문·글ID·원문 제목·sourceUrl 일치 → prepared displayTitle/captionInputTitle 일치 → 이미지 필요/원문 근거/권리 및 계획 확인 → 지원된 활성 생성 기록·원본 경로/해시/크기 확인 → 글별 배치/크롭/제목 전체 확인 → 별도 output/work → 실제 현재 oldRow 일치 → 실행 잠금 없음 → 한 글 제작 → complete 체크포인트와 실제 packaged runtime 확인 → 실제 PNG·원문/본문 해시 확인 → canonical writer로 해당 글만 등록 → 실제 저장소 표지/본문 읽기 성공 → 다음 글. 이미지가 없거나 잠금/정제/해시/버전/렌더 오류가 있으면 held로 보류하고 현재 결과를 바꾸지 않는다.

중복 키는 글ID+원문 sourceFingerprint+정제 제목/레이아웃+소비 자산/생성 기록 SHA+renderer/runtime이다. 동일 request/work와 완료 체크포인트를 유지하며 이미 같은 출력이 등록됐으면 다시 생성하지 않는다. 잠금을 강제로 삭제하지 않는다. 완료 기록은 글ID·회차·fingerprint·실제 cover SHA·자산 SHA·설치 런타임·본문 동일 여부·등록 버전·완료 시각이다. 예약 담당의 실패 인계 형식은 `{state:'held', reasonCode, missingEvidence, lastAttemptAt, nextAction}`이며 생산자의 held.reason을 근거로 남긴다. 자동 완료로 바꾸거나 전체 브릿지 큐를 갱신하지 않는다.

한 글 명령:

```powershell
& '.\scripts\이미지 있는 한 글 제작.ps1' -요청파일 'C:\작업\한글요청.json'
```

요청 형식은 threads-existing-cover-reproduction-v1, 절대 sourceRoot/output/work, 기존 reviewRound, 한 행의 id/title/oldRow/titleStyle/generatedCover다. title은 자산 대응용 원문 제목이며 정제 표시는 shared policy로 확정한다. generatedCover는 recordPath/generationRecordSha256/fileSha256를 요구한다. 이 명령은 승인된 기존 현재 표지의 별도 출력까지 수행한다. 현재 결과 등록, 대기166개 글의 최초 제작, 일반 source-batch 전체 제작, 업로드 및 실제 예약 생성은 별도 담당 범위다. 생성 대기나 실패를 캐시 완료 또는 글씨형 대체로 우회하지 않는다. 새 API·키·결제·계정·권한·사이트 업로드를 요구하지 않는다.

## 실제 증거와 업로더 인계

최신 결과는 자료/06_자동 제작 결과/최신 표지 결과.html과 글 제목별 현재 결과에 있다. 프로그램 실행.lnk 및 Launchers/Threads 게시글 평가.lnk는 `.38 --review-only`를 가리킨다. 프로그램에서 평가하기→아래로 읽기로 전체 본문/댓글을 읽고 뷰어로 돌아가기를 사용한다. 웹 그리드의 이미지는 실제 PNG 확대 링크이며 브라우저 바로가기 정책에 따라 링크가 열리지 않으면 자료의 바로가기를 직접 연다. 브릿지는 실제 `.38` 실행 PID를 확인했다. 이후 창 목록에는 해당 창이 없어 현재 계속 열려 있다고 주장하지 않는다.

증거: task-16/restored-cover70-current-20261009(전체199개70% 교체), task-16/source-label-cleanup-20261009(23개 태그 수정·199개 입력 정리·`.38` 실제 검수·uploader-handoff.json). 이전 `.8`85%와 거절된 스타일·과거 평가·원본은 복구 가능하게 보존했다.

업로더 원본 계약은 자료/06_자동 제작 결과/status.json과 각 production-plan.json이다. 13:06 UTC 읽기 전용 검증에서199개 목록과 대표3글40개 이미지 SHA/순서는 일치했다. 별도 업로더의 outputVersion은 reviewRound를 빠뜨려 리뷰 버전199개와 달랐고 표시 정제6개도 prepared displayTitle과 달랐다. bundle.source.label과 캡션 생성 입력은 준비된 정제 제목을 소비해야 한다. 캡션 제목 형식은 `[ 깨끗한 제목 ]`을 유지한다. 명시된 캡션은0개이며 평가 연동/캡션 생성/게시 완료로 기록하지 않는다. 다른 작업자의 업로더 코드·설치·계정·실제 게시는 수정하지 않았다.
