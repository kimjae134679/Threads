# 원문 컷 편집기

사용자 승인된 조작 시안을 실제 앱에 연결했습니다. Canva는 이번 범위에서 보류합니다.

현재 UI는 **원문 가져오기 → 컷 편집하기 → 미리보기 → 저장하기** 4단계로 나뉩니다. 표지 제목 렌더링은 기존 방식을 유지하고, 본문/댓글은 원본 사이트 UI를 그대로 노출하지 않고 별도 커뮤니티 양식으로 재구성할 수 있습니다.

- 게시판 카테고리(예: 자유게시판)는 결과 이미지에 표시하지 않습니다.
- 게시판 본문/댓글 계열은 서울남산체 EB 계열을 사용합니다.
- 게시글 원제목은 양진체 계열을 사용합니다.
- 댓글 페이지는 실제 댓글 문장만 표시하며 프로필, 닉네임, 날짜, 좋아요, 댓글 수, 입력창을 만들지 않습니다.
- 미리보기는 폰트 로딩 실패 때문에 작업 전체를 막지 않으며 사용 가능한 폴백으로 계속 렌더링합니다.

## 실행

Node 24 이상에서 저장소 루트의 `npm start`를 실행합니다.

- 기존 앱: `http://127.0.0.1:4173/app/` → 후보 선택 → 원문 이미지 또는 텍스트 입력 → **컷 편집기 열기**.
- 독립 편집기: `http://127.0.0.1:4173/app/source-cut-editor.html` → **원문 이미지 추가**.
- 입력 창에서 선택한 원문 파일과 제목은 같은 출처의 새 편집 창으로 전달됩니다. 텍스트 모드는 본문을 이미지로 렌더링해 넘깁니다. 후보 ID·원제목·출처 정보는 편집 파일에 보존됩니다.

## 분할선 사용

1. **본문 범위**를 누르고 출력할 부분을 드래그합니다. 원문 전체를 쓸 때는 **본문 전체 선택**을 누릅니다.
2. **여기서 페이지 나누기**를 누릅니다.
3. 원문에서 앞 장을 끝낼 위치를 클릭합니다. 그 선 위까지 앞 장, 아래부터 다음 장입니다.
4. 주황색 선을 끌거나 아래 숫자를 바꿉니다. **선으로 이동**으로 해당 위치를 바로 확인할 수 있습니다.
5. **삭제**를 누르면 인접한 두 조각이 합쳐집니다. 선이 없으면 선택한 본문 전체가 한 장입니다.

## 긴 글과 여러 장

전체 페이지 캡처 한 장 또는 순서대로 찍은 여러 장을 입력합니다. 원문 영역 안에서 휠로 스크롤하거나 **원문 이동** 상태에서 드래그합니다. 긴 범위를 선택할 때 아래쪽 끝으로 드래그하면 자동 스크롤됩니다. 확대 후에는 가로 스크롤도 가능합니다. 분할선은 원본 픽셀 좌표로 저장되므로 스크롤·확대에 영향을 받지 않습니다.

여러 장이면 **원문** 목록에서 바꿔가며 각각 자릅니다. **앞으로/뒤로**는 입력 이미지 순서를 바꿉니다. 표지는 어느 원문에서든 지정할 수 있으며 이미지 순서를 바꿔도 해당 표지와 함께 이동합니다. 여러 캡처에 겹친 부분이 있으면 본문 범위를 직접 조절합니다. 자동으로 이어 붙이거나 중복을 지우지는 않습니다.

데스크톱 앱에서는 게시글 링크로 공개 페이지를 캡처해서 바로 열 수 있습니다. 브라우저 HTML 단독 실행에서는 캡처 파일을 직접 넣습니다. 자세한 실행·제한은 `docs/SOURCE_CUT_DESKTOP.md`를 확인하세요.

## 제목과 강조

- 검정 테두리: 기본 8px, 2~20px 조절. 기존 자동 제작기의 2px 규칙은 그대로 둡니다.
- 기본 글씨색과 강조 색상을 각각 선택합니다.
- **강조할 단어**에 `북향, 남향`처럼 입력하면 제목에서 해당 단어가 나오는 모든 위치를 칠합니다. 줄이 나뉘어도 강조가 유지됩니다.
- 제목은 줄바꿈과 아래쪽 위치를 조절할 수 있으며 이미지 블러나 글자 그림자는 없습니다.
- **표지를 제목 없는 원본 조각으로 받기**를 선택하면 표지에서 제목과 그라데이션을 제외합니다.

## 저장과 내보내기

- **편집 저장**: `source-cut-project.json`에 원본 이미지·제목·색상·테두리·범위·분할선을 함께 저장합니다. 브라우저 다운로드 목록에서 저장 여부를 확인합니다.
- **편집 파일 열기**: 저장한 원본과 조작 상태를 복원합니다. 복원 후 본문 확인은 다시 해야 합니다.
- **전체 PNG를 ZIP으로 받기**: 범위·순서·분할 결과 확인을 선택하면 `cover.png`, `body-01.png` 등의 이미지와 `cut-manifest.json`을 ZIP 하나로 받습니다. manifest만으로는 원본을 복원할 수 없으므로 편집을 이어가려면 별도로 편집 저장을 사용합니다.
- 출력 너비 1080px, 높이는 각 선택 범위 비율을 그대로 따릅니다. 각 컷 높이가 다를 수 있으며 특정 플랫폼 게시 규격 검증은 하지 않습니다. 8192px보다 긴 결과는 분할선을 추가해야 내보낼 수 있습니다.
- 이미지 추가/영역/분할/순서 변경은 본문 확인을 해제합니다. 내보내는 동안 입력을 잠가 서로 다른 편집 상태가 섞이지 않도록 합니다.
- 원본은 이미지당 25MB, 합계 인코딩 80MB / 디코딩 8천만 픽셀 이하, 최대 30장입니다. 최종 ZIP은 128MB 이하로 제한합니다.

완성 이미지 다운로드는 게시 승인이 아닙니다. 이 편집기는 현재 기존 Source Package 승인 화면으로 변경을 되돌려 쓰거나 실제 계정에 게시하지 않습니다.

## 검증

`npm run check` main 통합 후 47개 suite / 142개 JavaScript 구문 검사 통과. 원본 좌표·분할 누락 방지·제목 강조·저장 복원·동일 출처 원문 전달을 확인했고, 생성 ZIP은 독립 Python zipfile 판독기로 검사했습니다. 실제 편집기 스크립트를 DOM 더블과 native Canvas에서 실행해 스크롤/확대, 분할, 색상/테두리 변경, 저장 복원, PNG ZIP 생성을 확인했습니다. 실제 HTTP 서버에서 신규 페이지와 모든 JS/CSS 경로가 200으로 응답했습니다.

이 실행에서 ZIP으로 생성된 실제 표지를 로컬에서 육안 검수했습니다. 첨부 원문을 사용한 예시 이미지는 공개 GitHub PR에 포함하지 않았습니다. 12px 테두리와 노란색 강조를 적용한 예시이며 기본값은 8px입니다. 실제 브라우저 입력·다운로드 E2E와 Windows 설치 확인은 아직 하지 않았습니다. 외부 게시 없음.

## 여백·중간 의견·폰트 프리셋

**장별 여백과 의견**에서 표지 또는 본문 장을 고릅니다. 위/아래/좌우 여백과 배경색, 최소 캔버스 높이를 바꿀 수 있습니다. 이미지 비율은 유지되고 추가 공간은 바깥쪽에 붙습니다. 원문 위 설명과 아래 의견을 각각 입력합니다. 긴 의견은 줄바꿈하며 너무 길면 분리 안내를 표시합니다.

글씨 스타일은 제목과 작성 의견에 공통 적용됩니다. Noto Sans KR 기반(400/900), 나눔고딕 기반(800)을 제공합니다. SIL OFL 원문·저작권 고지·변형 이름과 출처를 `app/fonts/`에 동봉했습니다. 선택한 글꼴에 없는 글자는 시스템 폰트로 대체해 내보내지 않고 안내합니다. 스크린샷 안에 이미 찍혀 있는 글자는 변경하지 않습니다.

**현재 폰트·굵기·색상·여백 저장**으로 이름 있는 프리셋을 저장합니다. 새 작업에도 쓸 수 있고 편집 파일에도 포함됩니다. 프리셋은 문구 내용은 복사하지 않습니다. **이 여백을 모든 본문에 적용**도 각 장의 문구는 유지합니다. 분할선을 추가/삭제하면 장 번호 기준의 문구 위치를 다시 확인합니다. 사라진 장의 문구는 보관 문구 안내에 남습니다.

소재 동기화에서 `## 중간 문구 초안`을 읽어 **소재를 찾을 때 적어둔 중간 문구**에 전달합니다. 기존 글을 확인 없이 일괄 다시 쓰지는 않습니다.

## 편집 기록과 자동화용 레퍼런스

- 원본 이미지 ID·크기, 표지/본문 좌표와 비율, 분할선, 여백·문구·폰트의 변경 전후를 시간과 함께 기록합니다.
- **이번 편집의 기준·이유**에는 사용자가 직접 이유를 적습니다. 좌표는 측정값이고 이 이유만 명시한 판단 기준입니다. 프로그램이 이유를 추측하지 않습니다.
- **이 결과를 다음 자동화의 기준 예시로 사용**은 완성 예시 표시입니다. 편집이 바뀌면 해제됩니다. 게시 승인과 무관합니다.
- 데스크톱은 앱 사용자 데이터의 `references/<projectId>/`에 원본 이미지(SHA-256 이름), `originals.json`, 변경 이력 `edits.jsonl`, 최종 `reference.json`을 자동 저장합니다. **PC 레퍼런스 폴더 열기**에서 확인합니다. 원본/기록을 GitHub나 외부 서버에 전송하지 않습니다.
- 브라우저는 **편집 저장** 또는 **편집 로그 받기**로 파일을 보관합니다. PNG ZIP에도 `edit-log.json`과 `reference-summary.json`을 포함합니다.
- 향후에는 기준 예시로 표시한 작업에서 여백 비율·분할 위치·문구 스타일을 분석해 추천 규칙을 만들 수 있습니다. 이 버전이 스스로 학습하거나 자동 게시하는 것은 아닙니다.
