## 사용자 전환 순서

1. 열려 있는 기존 편집에서 필요한 미저장 작업을 '편집 저장'으로 저장하고 완료 여부를 확인한다. 자동 편집 기록은 편집 프로젝트 저장을 대신하지 않는다.
2. 제작/저장 중인 작업을 마친 뒤 기존 편집·평가 창을 정상 종료한다. 종료 경고가 있으면 저장을 확인한 후 선택한다. 작업자는 강제 종료하지 않는다.
3. 공동 리뷰 바로가기를 열어 현재365글, 검토 회차와 기존 점수/메모/진행이 맞는지 확인한다. 잘못되면 평가를 계속하지 않고 이전 설치와 원본을 보존한 채 점검한다.
4. 공식 인증·전용 저장소·Android 기기 연결을 설정하기 전에 설치 ASAR 지문과 writer 역할을 다시 검증한다. 일반편집을 켠 상태로 모바일 교환을 실행하지 않는다.

## 역할 검증 범위

canonical 모듈 존재와 ASAR SHA만으로 일반편집을 적격이라고 판단하지 않는다. 일반편집의 batch/status 출력 경로는 아직 공동 평가 잠금을 사용하지 않으므로 교환 fleet에서 차단한다. 명시 review-only/읽기감사와 pc-review-run 역할만 허용한다. Electron 자식은 동일 실행 경로의 확인된 부모 역할을 상속하며, 불명확한 실행/부모·순환은 차단한다. 프로세스 조회 실패나 성공 표식 없는 빈 응답도 빈 fleet으로 인정하지 않고 차단한다. Threads 프로세스 command line은 메모리에서 역할만 판별하고 원문/인수/개인 프로필을 기록하지 않는다.

현재 프로세스 점검은 나중에 legacy 앱을 다시 실행하는 것을 막지 않는다. 온라인 교환 기간에는 일반편집·제작을 다시 켜지 않아야 한다. 제작은 교환을 끈 별도 단계에서 수행하고, 격리 제작·완료 증거·새 회차 활성화 절차로 현재 결과를 전달한다. 오래된 점수를 새 제작물로 옮기지 않는다.

실제 인증값·원격 설정·원격 접속·프로세스 종료는 수행하지 않았다. 최종 설치 모듈 전체 복사본 검증과 현재 실행/설치 SHA는 qa-local/mobile-canonical-20261008/writer-transition 및 최종 보고의 증거를 확인한다.
