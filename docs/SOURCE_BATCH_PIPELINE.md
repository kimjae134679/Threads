# 원문 선별 → ZIP → 게시용 이미지

현재 화면: `npm start` 후 `http://127.0.0.1:4173/app/source-batch.html`.

기존 후보 목록에서 관심 있는 글은 **이 글만 수집**으로 한 건씩 원문을 모읍니다. 전체를 처리하려면 **기존 원문 모으기**를 사용합니다. 저장된 HTML과 연결 이미지 후보를 로컬에 보관합니다. 이것만으로 게시용 이미지가 완성되지는 않습니다. 각 행에서 **원문 선별**을 열고 원문 제목, 필요한 본문 글 조각, 원본 이미지와 위치, 실제 댓글, 첫 장 문구와 배경으로 쓸 원문 조각을 확인합니다. 자동 초안은 확인한 게시글 본문 영역만 대상으로 문단을 묶고, 실제 댓글의 반응 근거가 있는 최대 세 건을 제안합니다. 원문과 대조했음을 자동으로 표시하지 않으며, UI 문구나 누락된 이미지가 있는지 사람이 확인해야 합니다.

**확인 후 ZIP 저장·이미지 제작**으로 현재 화면에서 원문 ZIP과 PNG ZIP을 연달아 저장할 수 있습니다. **현재 선택으로 미리보기**는 검수 전 표시가 있는 예시를 만듭니다. **원본·선별 기준 ZIP만 저장**으로 원본 바이트/선별 기준/이미지 파일/해시만 따로 묶을 수도 있습니다. 글을 고르는 단계에서 조각 뒤 여백·직접 쓴 중간 의견과 상업적 사용이 허용된 동봉 폰트·실제 굵기도 고르고 프리셋에 저장할 수 있습니다. 작성 중인 ZIP은 `needs_selection`이고 게시용 이미지로 간주하지 않습니다. **기존 원문 ZIP 수정**으로 다시 열어 검토할 수 있습니다. 본문·이미지·댓글 확인과 첫 장의 원문 글/이미지 배경이 모두 완료된 ZIP만 PNG 세트로 제작합니다. 표지에 실제 원문 이미지를 채우거나 원문 글 조각을 배경에 배치합니다. 단색 제목 표지는 생성하지 않습니다. 아래 미리보기에서 페이지 순서·여백·본문 빠짐을 확인합니다. PNG ZIP에는 제작 입력 원문 ZIP 자체와 manifest도 포함됩니다.

미확인 댓글이 남은 원문도 **검수 전 예시 보기**에서 원본 바이트·선택 이미지·근거를 검사한 뒤 워터마크가 들어간 이미지를 확인할 수 있습니다. 이 경로는 `threads-curated-preview-v1`로 구분하고 제작 완료 상태를 올리지 않습니다. 원본 이미지의 가로세로 비율에 맞춰 표지/본문의 공통 캔버스 높이를 정하고, 본문 이미지 한 장을 자르지 않고 한 페이지에 배치합니다.

저장 폴더를 선택하면 그곳에 파일을 저장하고, 선택하지 않으면 브라우저 다운로드로 받습니다. 기존 파일을 같은 폴더에서 다시 만들 때는 새 이름을 써서 덮어쓰지 않습니다. 자동 수집은 기존 후보에 기록된 정확한 공개 HTTPS URL만 대상으로 합니다. 원문 URL 없음·로그인 차단·원본 미디어 부족은 건별로 표시합니다. 직접 가진 HTML/TXT/JSON과 이미지는 화면의 **원본 폴더 선택 → 원본 목록 열기**에서 각 건의 선별을 엽니다.

원문 ZIP을 만드는 실제 판정 기준과 파일 구조: [SOURCE_BUNDLE_GUIDE.md](SOURCE_BUNDLE_GUIDE.md). 사진/원문 스크린샷으로 추가 조정이 필요하면 [수동 컷 편집기](SOURCE_CUT_DESKTOP.md)에서 이어서 수정합니다.

정확한 TXT 형식은 `[TITLE]`, `[BODY]`, `[COMMENTS]`이며 본문 이미지가 들어갈 위치에는 `[IMAGE:원본파일명]`을 적습니다. 댓글을 확인하지 못했다면 없음으로 확정하지 않습니다. JSON은 `schema=threads-verbatim-source-v1`, `verbatim=true`, 원본 title/body, 실제 comments를 사용합니다. 과거 `BODY_SEQUENCE` 요약·Jev 점수는 원문 전문이 아닙니다. HTML 추출은 출처 화면과 글자/줄바꿈이 다를 수 있어 선별 화면에서 확인 표시를 따로 요구합니다.

제작된 ZIP은 로컬 결과이며 인스타그램 게시/원본 재사용 권한 승인과 별개입니다. 수집 파일과 실제 입력 ZIP은 로컬 `data/runtime/source_pipeline/` 또는 선택한 PC 폴더에 있고 GitHub에 자동 업로드하지 않습니다. 권리·개인정보·최종 결과물 검수는 04 단계에서 수행합니다.
