# Threads Cut Editor 자체 점검 (2026-09-29)

## 판정

현재 결과를 AAA.zip과 동급의 게시 품질로 판정하지 않는다. 실제 원문 이미지 8장을 사용한 검수 전 예시만 만들었다. 본문 전문, 이미지 위치, 댓글, 권리·개인정보 확인이 남아 있어 게시 승인은 false다.

## 남은 자료 상태

- 후보 1,084건 중 원본 이미지가 첨부된 것은 1건(8장), 나머지 1,083건은 이미지가 없다.
- 56건은 원문 주소도 없어 출처 확인이 필요하다.
- content.txt는 후보 요약 기록이며 본문 원문이 아니다. 이미지·본문·댓글을 추측하거나 임의로 채우지 않는다.
- AAA.zip은 22장의 스타일 참고 화면이다. 게시 순서와 정확한 원문 텍스트를 그 ZIP에서 추정하지 않는다.
- 검수 전 예시 9장은 형식과 렌더링만 점검한다. 원문 대조와 게시 승인 완료를 의미하지 않는다.

검증: 173개 JavaScript 구문 검사, 57개 테스트 묶음, 편집기 smoke, 실제 8장 원문으로 9장 검수 ZIP 생성, Windows 0.2.6 ZIP 배포를 통과했다. 표지 위 글씨는 아직 원본 인물 일부와 겹친다. AAA.zip과 동급이라고 주장하지 않는다.

## 0.2.7 재점검과 보완

이전 9장 예시는 테스트 코드가 원문 TXT를 합성하여 만든 결과였다. 실제 제작 창에서 바탕화면 개별 후보 폴더를 직접 선택하는 경로가 없어서 같은 결과를 사용자가 재현하기 어려웠다. 저장된 후보의 `manifest.json + media/`와 Source Package의 `SOURCE.md + original/`을 제작 창 첫 화면에서 읽도록 연결했다. 저장된 제목과 이미지 파일 순서만 가져오며, 본문·댓글을 임의로 채우지 않는다.

후보 이미지의 SHA-256과 수가 manifest와 다르면 거부한다. Source Package에 intake-manifest가 있으면 원본 해시를 대조한다. 검수 전 버튼은 `previewOnly=true`, `publicationAllowed=false`인 예시 ZIP을 만든다. 첫 장 글씨 크기와 위·왼쪽 위치를 조절할 수 있다. 실제 8장으로 제목을 짧게 편집한 예시는 방송 자막과 인물 얼굴을 피하도록 배치했다. 최종 제작 안내의 '게시용' 표현은 게시 승인과 혼동되지 않게 고쳤다.

현재 저장소와 바탕화면 후보 자료를 다시 확인한 결과, 이미지가 있는 고유한 원문은 같은 TheQoo 게시물 1건이다. 본문 글·댓글 전문 및 게시 권한을 확인할 자료는 없다. 0.2.7을 AAA.zip 수준의 게시 완료본으로 판정하지 않는다.

## 다음 완료 기준

1. 사용하려는 개별 후보의 원문 글·이미지·댓글을 순서와 위치까지 실제 자료로 확보한다.
2. 인물·UI·자막과 새 제목이 겹치지 않는지 모든 장을 눈으로 검수한다.
3. 권리·개인정보와 게시 허용 상태를 별도 책임자가 확인한다.
4. 그때 최종 PNG ZIP을 게시 결과로 판정한다.

## 0.2.8 재검토

0.2.7의 실제 표지는 1080×675 가로형이었고, 본문 이미지마다 한 장을 써서 화면의 상당 부분이 비었다. AAA.zip의 모바일 게시물 흐름과 비교해 결과 품질이 부족했다. 저장 이미지 전용 결과를 1080×1350 세로형으로 통일하고, 표지에는 원본 사진 전체를 보존한 채 짧은 제목을 상단에 놓았다. 본문은 저장 순서대로 두 이미지를 한 장에 배치한다. 실제 원본 여덟 장으로 표지 포함 다섯 장을 다시 만들어 시각적으로 확인했다.

바탕화면 후보 1,084건이 모두 프로그램 입력 폴더에 있어 사용 가능한 한 건을 찾기 어려웠다. 전체 기록은 01_후보 기록에 보존하고, 02_프로그램 입력에는 SHA-256 기록이 있는 원본 한 건만 작업 사본으로 둔다. 두 폴더의 역할과 실제 실행 순서를 첫 안내문에 적었다. 첫 화면에는 컷 편집과 빠른 검수 이미지 제작을 별도 버튼으로 드러냈다.

첫 화면의 폴더 불러오기도 이제 후보 manifest 또는 Source Package intake-manifest의 이미지 순서와 SHA-256을 검사한다. 저장 이미지 폴더만 선택한 경우 검증 기록이 없다고 표시한다. 원문 대조가 필요한 편집 출력에는 검수 전·게시 금지 표시를 넣고 ZIP manifest도 previewOnly=true, publicationAllowed=false로 남긴다. 코드 검사, 이미지 생성 smoke 및 원본 변경 거부 테스트를 다시 실행한다.

여전히 실제 게시글의 본문·댓글 원문과 이미지가 본문 어디에 놓였는지는 확보되지 않았다. 권리·개인정보 확인도 남았다. 따라서 이 결과는 레퍼런스와 구성을 비교할 수 있는 검수용 예시이며 게시 완성본이라는 주장은 할 수 없다.

## 0.2.9 폴더 자동 제작

첫 화면에 전체 폴더 버튼과 진행, 중지, 결과 폴더 열기를 추가했다. `01_후보 기록/index.json`의 모든 1,084건을 순회하며, 저장 이미지와 SHA-256을 검증한 후보만 렌더링한다. 결과 폴더에는 후보별 펼친 `rendered/slide-*.png`와 ZIP을 저장하고 `status.csv` 및 `status.json`에 제작, 이미 완료, 원본 부족, 실패 사유를 남긴다. 다시 실행할 때 입력 지문과 ZIP 및 각 PNG 해시가 같으면 건너뛰며, 결과 PNG가 사라지면 재생성한다.

실제 저장 자료로 앱 IPC를 두 번 실행한 검사에서 첫 실행 1건 제작, 1,083건 원본 부족, 실패 0건이었다. 두 번째는 1건 건너뜀, 1,083건 원본 부족이었다. 제작된 한 건은 원본 여덟 장을 이용한 1080×1350 다섯 장이며 검수 전 표기와 `publicationAllowed=false`를 유지한다. 이 자동화는 원본이 없는 글과 댓글을 만들어내지 않으며 게시 완료 품질을 보장하지 않는다.
