## 목표와 완료 기준

사용자 목표는 원문을 자동으로 이미지화하되, 레퍼런스처럼 첫 장을 눌러 보고 싶고 마지막 장까지 불편 없이 읽히는 결과를 전달하는 것이다. 코드·빌드 통과와 PNG 생성 개수는 시각적 합격 근거가 아니다.

- 표지: 소재의 갈등·반전·질문이 즉시 보이는 문구, 실제 내용을 설명하는 원본 사진, 읽히는 글꼴·대비·강조·배치.

- 가독성: 360px 너비에서 제목을 바로 읽고 본문을 확대 없이 읽는다. 긴 원본 이미지의 글줄·말풍선·의미를 절단하지 않는다.
- 완성도: 광고·사이트 메뉴·닉네임/날짜/반응 UI·쓸데없는 중복·빈 장·의미 없는 큰 여백·사진 왜곡·제목 가림이 없다.
- 전달: 최종 PNG 세트, 원문과 제작 계획, 실제 검수 상태, 바로 열리는 프로그램과 결과 위치를 함께 확인한다.

1. 자동 형식 선택은 사진의 픽셀 분석과 글 길이가 중심이다. 사진의 소재 적합성, 표지 문구의 흡인력, 피사체·제목의 시선 배치는 후보별 제작 판단이 필요하다.
2. 기본 표지 제목은 원제목 또는 기존 계획을 사용한다. 원문 근거를 가진 짧은 훅과 핵심어 강조를 후보별로 정하고 검수해야 한다.

4. 기존 레퍼런스 가이드와 감사 문서에는 0.3.1의 417건·2,886장 수치가 남아 있다. 최신 handoff의 398건·3,209장과 혼동하면 안 된다.

## 작업 순서

### 1. 실제 자료·실행 위치 복구와 정리

원본 입력 1,084건과 레퍼런스 ZIP을 기준으로 실제 파일 목록·해시·바로가기 대상을 대조한다. 원본·설치파일·현재 결과·검수본·이전 버전을 구분한다. 목록의 경로마다 실제 파일을 확인한다. .3.1 실행파일을 .3.3처럼 설치하지 않는다. 원본 입력은 이동 대신 연결한다.

### 2. 대표 20건을 레퍼런스와 비교해 재작업

사진, 긴 글, 짧은 글, 밝은 캡처, 검은 대화, 만화/말풍선, 혼합 이미지·본문을 포함한다. 각 후보의 원문을 읽고 다음을 editorial-plan.json에 근거와 함께 기록한다.

- 참고 레퍼런스 게시물과 선택 이유
- 표지에 적합한 실제 원본 이미지/사용 영역
- 표지 문구, 원문 근거, 강조할 단어, 제목 줄바꿈·위치·크기
- 장별 원문 문단/이미지 ID, 전달 목적과 순서
- 원본 이미지의 안전한 사용 영역과 분할 경계
- 인기 댓글 근거, 마지막 장과 결말, 원문 누락 여부
- 작성 의견은 원문·실제 댓글과 구분

기존 결과와 개선 결과의 첫 장·중간 장·마지막 장을 같은 360px 크기로 직접 비교한다. 자동 지표 외에 원문과 모든 장을 대조한다.

### 3. 검증된 제작 판단을 프로그램에 반영

큰 제목·핵심어 대비·피사체 보호·원문 크기·내용에 맞춘 여백·의미 단위 장 나눔을 재사용 가능한 규칙으로 반영한다. 기존 editorial-plan을 실제 렌더러가 사용하게 하고 형식별 실패는 구체적인 보류 사유로 남긴다. 디자인 변경만으로 원문 캐시/확인 상태를 성공으로 만들지 않는다.

### 4. 전체 결과에 적용하고 파일 단위로 감사

대표 20건의 수정으로 해소된 문제를 확인한 뒤 기존 398건의 재제작 범위를 정한다. 입력·원문 ZIP·제작 규칙·PNG 해시와 마지막 내용·이미지 연속성·글자 겹침을 검사한다. 품질 미달과 자료 부족을 구분한다. 진행은 20건 단위로 총수/완료/재작업/보류를 기록한다.

### 5. 최종 전달 흐름 확인

글 제목·첫 장 썸네일·한국어 상태·이유·완성 이미지 보기·원본 열기·결과 폴더 열기가 한 목록에 있어야 한다. 목록의 존재와 실제 파일 존재를 함께 확인한다. 재실행·중단·재개·결과 복원과 폴더 경로를 실제 설치본에서 확인한다.

## 이번에 실제로 정리한 폴더

바탕화면 `Threads Cut Editor 자료`를 다시 만들고 입력 원본 1,084건을 Junction으로 연결했다. 레퍼런스 원본 ZIP은 SHA-256 일치를 확인해 `02_레퍼런스/원본 ZIP`에 보관하고 `게시물 보기`에 계정별 열람 자료를 풀었다. 루트의 `레퍼런스 보기` 바로가기는 실제 index.html을 가리킨다. `00_먼저보기`에는 이번 계획과 현재 확인 상태를 두었다.

실행본과 최신 결과는 아직 복구·검증하지 않았다. `03_배포 설치파일`과 `06_자동 제작 결과`가 비어 있는 상태를 숨기지 않는다. 기존 원본·사용자 백업은 삭제하지 않았다. 이번 확인 중 만든 임시 이미지·inventory·스크립트는 종료 전에 제거한다.
