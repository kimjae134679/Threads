# Unified private material catalog

Open `/materials/` from the review application's **전체 자료·수동 업로드** link, or the current post's **이 글 본문·태그·이미지 자료** link. Existing review controls, random order and asynchronous verdict saves remain independent.

The catalog reads every producer status entry, every current stored post, archived posts, saved editing history, the prior state backup, and named state snapshots and their edit histories inside `.local/replaced/<operation>/`, plus automatic replacement `previous-post.json` archives and their saved histories. It does not replace or import these records. Identical saved post objects group their source references; distinct content or review evidence remains separate. Producer output versions use the existing `productionVersion` identity and read their native saved images/captions without importing them. They remain a separate unreviewed scope and do not infer finalized common tags; saved Threads text is preserved independently from the current editor’s title-only convention. The current producer status, caption-file metadata and state are refreshed on demand, so new records use this same representation automatically.

Current final decisions use the existing version/basis validation. A review note can display **검토 중 · 미확정** while the underlying decision remains `unreviewed`. Historical passes and incomplete editing snapshots never receive `currentFinalPass`. Source availability, rights and safety remain independent conditions; `publicationAuthorized` is always false. Producer triage status is preserved independently of review status. Reading or downloading creates no pass, transport or schedule.

A per-post, per-platform ZIP contains ordered original images (`01.png`, `02.jpg`, etc., preserving actual MIME and bytes), `보기.html`, `본문.txt`, `해시태그.txt`, `전체문안.txt`, `검토상태.txt`, and `자료정보.json`. Threads topic metadata is a separate text file. Current final text follows the application's existing final-caption contract. Raw tags are also preserved in metadata. Historical complete states expose their saved body and tag inputs; incomplete editing snapshots omit the unavailable whole-caption file instead of inferring missing common tags or final reviews. Intake records expose their pinned original source files and never receive a publish-looking ZIP.

Files and paths are restricted to named private catalog roots, regular files and saved hash identifiers. Image reads verify SHA-256, MIME signatures and sequence before download. Concurrent ZIP creation is bounded to one export; CRC computation yields between chunks so review saves remain responsive. ZIP generation is on demand and does not duplicate all operating images into new folders.

`GET /api/materials` returns a small list, counts and source warnings. `GET /api/materials/<key>` returns one saved record. Image/source/package routes use the record key. Changed current decisions or content make obsolete keys fail closed. `GET /api/materials/audit` checks referenced files without changing state. The optional CLI `tools/audit-materials.mjs` saves its report to a user-specified private project path and compares state, decision, selection, producer and evaluation hashes before/after.

Private content, images, evaluations and generated audit reports stay outside the Git source. Code and synthetic fixtures can be committed locally. Publication requires separate authorization.
