# 자동 수신 연결 인계 — 준비판 0.1.1

사용자는 인터넷으로 최신 글과 이미지를 자동 받는 APK를 요청했습니다. 현재 준비판은 그 목표의 완료 결과가 아닙니다. UI·오프라인 평가·큐·충돌 계약·HTTPS client는 준비됐지만 실제 글 수신이나 PC 평가 반영은 한 번도 성공 검증하지 않았습니다. 모의 데이터는 테스트 전용이며 사용자 APK에 넣지 않습니다.

## 정확한 미연결 이유

1. 확인된 PC `server.mjs`는 127.0.0.1 로컬 서버이며 인터넷 리뷰 API가 아닙니다.
2. ProjectBridge3.0도 로컬 인증 API + 비공개 GitHub 작업 중계입니다. 작업용 토큰을 APK에 넣어 사용자 리뷰 서버로 사용할 수 없습니다.
3. 인터넷에서 앱이 접근할 기존 승인된 HTTPS 리뷰 서비스 URL과 앱 사용자용 기존 인증 방식이 확인되지 않았습니다.
4. 서버의 versioned manifest/PNG + 사용자별 operationId dedup/CAS + PC canonical 평가 연결 adapter도 현재 경로에는 없습니다.

일반 Android INTERNET 선언 자체는 금지되지 않았고 이번 준비판에 포함했습니다. 이를 선언한다고 서버나 인증이 생기지는 않습니다. endpoint 미설정·의도적인 네트워크 비활성은 미연결 사실을 숨기지 않기 위한 상태입니다. 새 포트 개방, 공개 노출, 키/OAuth 생성, 지속 권한 확장이나 새 유료 서비스는 실행하지 않았습니다.

## 부모가 제시할 가장 작은 선택지

| 선택 | 사용자에게 필요한 최소 정보·조치 | 후속 담당 작업 |
|---|---|---|
| 이미 쓰는 비공개 웹서비스가 있음 | 그 서비스의 HTTPS 주소와 기존 로그인 방법만 알려주기. 비밀키/토큰을 채팅에 보내지 않음. | 승인된 기존 서비스인지 읽기 전용 확인 → 기존 사용자 인증을 사용하는 리뷰 adapter → 실제 수신/평가왕복·오프라인 재접속 검증. 새 계정·OAuth/key 생성은 하지 않음. |
| 해당 서비스가 없음 | “없음”이라고 확인. 서버 만들기/기존 호스팅 추가 사용 여부는 부모가 비용·공개범위·기존 인증을 구체화한 뒤 별도 승인 받기. | 현재 준비판 유지. 승인 전 새 서비스/포트/공개호스팅/키를 만들지 않음. 구현만으로 자동수신 완료라고 안내하지 않음. |

사용자에게 파일을 넣거나 인터넷 포트를 열거나 GitHub/브릿지 토큰을 APK에 입력하라고 요구하지 않습니다. 특정 기존 호스팅이 이미 승인됐다는 증거는 이번 작업에서 찾지 못했으므로 임의 서비스명을 확정하지 않습니다.

## 연결 후 완료 검증 기준

- 사용자 설치 APK가 실제 최신 reviewRound/글ID/outputVersion/이미지 SHA를 인터넷에서 자동 수신. 자동 카테고리·시스템 테마·PNG 순서를 확인.
- 기존 사용자 인증으로 기기에서 작성한 점수/메모/기준/검토결정이 해당 PC canonical 평가·진행에 반영되고 재열기에 동일하게 읽힘.
- 서버에서 동일 operationId 재전송이 중복 쓰기를 하지 않으며, 응답 유실/기기간 revision 충돌/오프라인 재접속을 실제 경로에서 검증.
- 새 제작본에서 옛 점수는 빈 상태. stale round/version/criteria 저장이 서버에서도 거부됨.
- 게시 승인은 검토 의사 기록과 별도 실제 게시 절차로 구분. 이 APK는 게시를 실행하지 않음.

실제 데이터 왕복 전에는 “미연결 준비판”, Android 기기 설치 검증 전에는 “빌드·브라우저 UI 검증”으로 안내합니다.
